# Trading Success Report Dashboard

A responsive web dashboard for viewing trading success reports generated by the Google Apps Script.

## Features

- **Overview Dashboard**: Key metrics and performance statistics
- **Multi-Day Analysis**: Track trades that remain profitable over multiple days
- **Indicator Effectiveness**: See which indicators correlate with success
- **Earnings Timing**: Analyze pre vs post-earnings performance
- **Strategy Comparison**: Compare performance across different strategies
- **Top Plays**: View the best performing trades with their indicators

## Setup

### 1. Deploy the Google Apps Script Web App

1. Open your Google Apps Script project
2. Add the `16_WebApp.js` file to your project
3. Go to Deploy > New Deployment
4. Choose "Web app" as the type
5. Set:
   - Execute as: Me
   - Who has access: Anyone (or adjust based on your needs)
6. Deploy and copy the Web App URL

### 2. Configure the Dashboard

1. Open `src/config.js` and update the `WEB_APP_URL` with your deployed URL
2. If you want to restrict access, implement authentication in both the Web App and dashboard

### 3. Host the Dashboard

#### Option A: Local Development
```bash
# Use any simple HTTP server
python -m http.server 8000
# or
npx http-server
```

#### Option B: GitHub Pages
1. Push this folder to a GitHub repository
2. Enable GitHub Pages in repository settings
3. Access at: `https://[username].github.io/[repo-name]/`

#### Option C: Netlify/Vercel
1. Connect your repository
2. Deploy with default settings
3. No build step required (static site)

## Usage

1. The dashboard automatically loads the latest report data
2. Click "Refresh Data" to manually update
3. Navigate between tabs to view different analyses
4. Charts are interactive - hover for details

## Customization

### Adding New Metrics

1. Update the Google Apps Script to include new data in `storeSuccessReportData()`
2. Add corresponding UI elements in `index.html`
3. Update `app.js` to render the new data

### Styling

- Edit `src/styles.css` to customize colors, fonts, and layout
- The dashboard uses CSS variables for easy theming

### Data Update Frequency

By default, the success report is generated daily at 9 AM. You can:
- Modify the trigger schedule in Google Apps Script
- Add real-time data fetching if needed
- Implement caching strategies for better performance

## API Endpoints

The Web App provides these endpoints:

- `?action=getReport` - Get the complete success report (default)
- `?action=getLatestUpdate` - Get timestamp information
- `?action=refreshReport` - Manually trigger report regeneration

## Security Considerations

1. **Access Control**: Configure Web App permissions appropriately
2. **CORS**: The Web App sets appropriate CORS headers
3. **Data Sensitivity**: Don't expose sensitive trading data publicly
4. **Rate Limiting**: Consider implementing rate limits for the Web App

## Troubleshooting

### No Data Showing
1. Check that the success report has been generated in Google Sheets
2. Verify the Web App URL is correct in config.js
3. Check browser console for errors
4. Ensure Web App permissions allow access

### Charts Not Rendering
1. Ensure Chart.js is loading properly
2. Check that data format matches expected structure
3. Verify no JavaScript errors in console

### Slow Performance
1. Consider caching data locally
2. Optimize Google Apps Script queries
3. Implement pagination for large datasets
