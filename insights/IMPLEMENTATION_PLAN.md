## Context

The current [/insights](platform/src/routes/InsightsPage.tsx) tab is a generic Gemini 2.0 Flash chat box with 4 persona modes. It is **not actionable**: the system prompts reference signals, backtest results, GEX, and playbooks that the LLM cannot actually see — only the user's typed message and 6 messages of history reach the model. No structured data is ever grounded into the prompt. A user has to know what to ask, and even then the answer is LLM-hallucinated context, not the platform's real state.

The user wants the opposite: **open the tab, see a ready-to-act structured analysis** of the active ticker — direction, thesis, entry/stop/target, catalysts, strat status, bull/bear debate summary, risks — auto-refreshed daily, re-runnable on demand. Chat becomes a secondary sub-tab, not the default. The inspiration is [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents), but we adapt rather than port: the high-value pieces are the **bull/bear debate + judge**, **two-tier model routing**, and **reflection memory**. Everything else in that repo is inferior to what this codebase already has (Cloud SQL with SPY/IWM/QQQ intraday + options + indicators, `premarket_analysis` table, `StratClassifier`, 330K historical signals, backtest metrics, journal entries).

This plan keeps the `/insights` route but fully replaces what it renders and what the backend router does.

## Design Principles

1. **Structured-first, chat-second.** Landing view is a scannable report generated by the agent pipeline. No prompt required. Chat lives at `/insights/chat` as a sub-route.
2. **Ground every LLM call in real SQL data.** Analysts consume deterministic SQL/GCS summarizers that emit typed JSON — LLMs reason *over* that JSON, they don't fetch it.
3. **Precompute daily, re-run on demand.** A scheduled Cloud Run job writes fresh reports for SPY/IWM/QQQ to Cloud SQL at market close. The page reads the cached row instantly. A "Re-analyze" button triggers an on-demand run.
4. **Provider-agnostic LLM client with admin-selectable models per role.** A single abstract `LLMClient` interface supports multiple providers (Vertex Gemini, Anthropic, OpenAI) behind one call signature. The pipeline assigns a model *per agent role* (analyst, bull, bear, judge, trader, risk, portfolio_manager), each configurable at runtime from a new **Admin → Model Routing** dashboard. **Start in production with Vertex Gemini for every role** (reusing the existing `.gcp-key.json` service account — no new secrets required on day one). Wire every non-Gemini provider (Anthropic, OpenAI) in code so swapping is a dropdown change, not a refactor. Prompt caching is implemented where the provider supports it (Anthropic cache_control, Gemini context caching) and is a no-op otherwise.
5. **Force structured output.** Every agent emits Pydantic-validated JSON. No regex extraction from prose.

## Architecture

### Agent pipeline (in `lib/agents/`)

```
                   ┌─ market_analyst ─┐
                   ├─ strat_analyst  ─┤
ticker, date ──► ──┤                 ├──► bull_researcher ─┐
                   ├─ options_analyst┤                     ├──► research_manager (judge)
                   └─ catalyst_analyst┘                    │           │
                                      └─ bear_researcher  ─┘           ▼
                                                                      trader
                                                                        │
                                                   ┌── aggressive ─────┤
                                                   ├── conservative ───┤ (risk debate)
                                                   └── neutral ────────┘
                                                                        │
                                                                        ▼
                                                                portfolio_manager
                                                                        │
                                                                        ▼
                                                         InsightReport (Pydantic)
```

- **Analysts (parallel)** each receive a structured JSON context bundle from a deterministic summarizer — no tool calling, no hallucination surface.
- **Bull/Bear researchers** (1 debate round default) — adversarial framing over the same analyst outputs.
- **Research manager** — judges the debate, produces the investment thesis.
- **Trader** (structured output) — emits `direction / entry / stop / target / confidence / invalidation`.
- **Risk debate** (3 personas, 1 round default) — each persona returns a JSON critique.
- **Portfolio manager** (structured output) — final `InsightReport` with all sections merged.

Every node calls `llm_client.complete(role=<role>, ...)` — the client looks up the configured model for that role from the `model_routing` Cloud SQL table (see Admin Dashboard below) and dispatches to the correct provider adapter. **Current config (as of 2026-05-11)**: all 7 roles route to `vertex:gemini-3.1-flash-lite` on the `global` endpoint. Day-two config: admin flips specific roles to a different Vertex model, or to Anthropic/OpenAI, from the UI. _Note: the original day-one config was `vertex:gemini-2.0-flash` on `us-east1`; migrated 2026-05-11 after DSQ-contention 429s — see `lib/agents/vertex_adapter.py` for the location/model selection logic._

Orchestration is a **hand-rolled async orchestrator** (~200 lines) — no LangGraph. The graph is 11 nodes; Python `asyncio.gather` for the parallel analyst tier and sequential awaits for the rest is simpler to debug and has no framework lock-in.

### Deterministic summarizers (the "data layer")

These are pure-Python functions that query existing tables and return typed dicts. No LLM. They are what makes this system actually grounded.

- `summarize_market_context(ticker, date)` — reads [market_data_daily](gcp/schema.sql) for OHLCV, `sma_200`, `ema_20`, `macd*`, `bb_*`, `price_vs_ema20`. Computes % distance from key MAs, regime tag (trending/ranging), 20-day realized vol.
- `summarize_strat_status(ticker, date)` — reuses [StratClassifier](lib/strat.py) via the `premarket_analysis` Cloud SQL row. Emits last candle type, in-force combo, FTFC score + direction, trigger high/low.
- `summarize_options_flow(ticker, date)` — queries [etf_options_snapshots](gcp/schema.sql) for the latest `data_source='alphavantage'` row, computes put/call volume ratio, max-pain strike, top OI strikes, IV percentile.
- `summarize_signals_history(ticker, lookback=30)` — reads [signals router data source](platform/api/routers/signals.py); emits recent signal count, win rate of last N fires, current active signals.
- `summarize_backtest_metrics(ticker)` — reads latest run from [backtest router](platform/api/routers/backtest.py); emits win rate, profit factor, Sharpe, max DD, expectancy.
- `summarize_catalysts(ticker, date)` — reads [economic_events](gcp/schema.sql) and earnings calendar; emits next 5 events in the next 14 days with impact tags.
- `retrieve_similar_journal(ticker, setup_embedding, k=5)` — pgvector lookup on `journal_entries`. Returns past trades with similar setup for reflection memory.

The bundle is cached per (ticker, date) — same day re-runs reuse it.

### Output schema (`lib/agents/schema.py`)

```python
class InsightReport(BaseModel):
    ticker: str
    as_of: datetime
    direction: Literal["long", "short", "flat"]
    conviction: Literal["low", "medium", "high"]
    thesis: str                          # 2-3 sentences
    entry_zone: tuple[float, float]
    stop: float
    targets: list[float]                 # ordered
    invalidation: str                    # what kills the trade
    time_horizon: Literal["intraday", "swing", "position"]
    key_levels: dict[str, float]         # support/resistance/pivot
    strat_status: StratSnapshot
    catalysts: list[Catalyst]
    bull_case: str
    bear_case: str
    risk_flags: list[RiskFlag]           # from risk debate
    supporting_signals: list[SignalRef]
    similar_past_trades: list[JournalRef]
    confidence_score: float              # 0-1
    model_versions: dict[str, str]       # for reproducibility
    run_cost_usd: float
    run_latency_ms: int
```

Every field is enforced via Claude's tool-use structured output mode. No prose parsing.

### Storage

New Cloud SQL table `insight_reports` (add to [gcp/schema.sql](gcp/schema.sql)):

```sql
CREATE TABLE insight_reports (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ticker VARCHAR(10) NOT NULL,
    as_of TIMESTAMPTZ NOT NULL,
    report JSONB NOT NULL,
    model_versions JSONB NOT NULL,
    cost_usd NUMERIC(10,4),
    latency_ms INT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (ticker, as_of)
);
CREATE INDEX idx_insight_reports_ticker_date ON insight_reports (ticker, as_of DESC);
```

Enable `pgvector` extension and add an `embedding VECTOR(768)` column to `journal_entries` for reflection memory (idempotent migration).

Add the `model_routing` table that drives the admin dashboard:

## Cost & Latency Budget

Cost depends entirely on which provider/model each role is routed to. The `llm_client` records `provider`, `model`, `input_tokens`, `output_tokens`, and per-call `cost_usd` into the `InsightReport.model_versions` and `cost_usd` fields so every run is attributable.

- **Day-one (all Vertex Gemini 2.0 Flash)**: ~$0.01–$0.03 per full run, <15s latency target with parallel analysts. 3 tickers × 1 daily run = ~$0.10/day.
- **All-Anthropic config (Haiku analysts + Sonnet managers)**: ~$0.19 per run, ~$0.60/day for 3 tickers. Prompt caching on system+context blocks cuts subsequent runs ~5×.
- **Mixed**: the admin dashboard's "Test" button returns the estimated cost per role so the user can preview before saving.
- On-demand refreshes are rate-limited to 1/ticker/minute at the router.
- Chat sub-tab cost stays on Gemini (unchanged — independent of the agent pipeline routing).

## Audit Findings & Remediations

An independent Plan-agent audit identified the following. Each item is CRITICAL / IMPORTANT / NICE-TO-HAVE, followed by the **fix folded into this plan**. Implementation must satisfy all CRITICAL + IMPORTANT items before the PR lands.

### CRITICAL

1. **Schema migration is not idempotent.** `INSERT INTO model_routing` will conflict on re-run; `CREATE TABLE` / `CREATE EXTENSION` also need `IF NOT EXISTS`. Cloud SQL PG15 also requires `cloudsql.enable_pgvector` — may need a maintenance window.
   - **Fix**: Use `CREATE EXTENSION IF NOT EXISTS vector;`, `CREATE TABLE IF NOT EXISTS ...`, and `INSERT ... ON CONFLICT (role) DO NOTHING` for all seeds. Check Cloud SQL pgvector availability as verification step 0 (`psql -c "SHOW cloudsql.enable_pgvector"`); if disabled, open a ticket and patch flag before merging.

2. **`UNIQUE (ticker, as_of)` breaks on same-day re-runs.** Daily job + on-demand refresh will both write the same date.
   - **Fix**: Change the constraint to `UNIQUE (ticker, as_of)` where `as_of` is a full `TIMESTAMPTZ` (not truncated) and add `ON CONFLICT (ticker, as_of) DO UPDATE SET report = EXCLUDED.report, ...` in the upsert path. "Latest for ticker" reads use `ORDER BY as_of DESC LIMIT 1` on the existing btree index. The `GET /api/insights/report/{ticker}` endpoint returns the latest row, `history` returns the ordered list.

3. **FastAPI `BackgroundTasks` is not durable on Cloud Run.** Scale-to-zero will drop in-flight pipeline runs; `run_id` polling has nothing to poll.
   - **Fix**: Add an `insight_runs` status table (`id UUID PK, ticker, status ENUM('queued'|'running'|'done'|'failed'), started_at, finished_at, error TEXT, report_id UUID FK`). `POST /refresh` inserts a `queued` row and enqueues a Cloud Tasks message targeting the existing Cloud Run job (`gcp/insight_pipeline_job.py`) with the run_id. The job flips status as it runs. `GET /api/insights/runs/{run_id}` polls the table. Cloud Tasks queue setup added to `gcp/deploy.sh`. BackgroundTasks is only acceptable for local dev and is behind an `if env == 'local'` branch.

4. **Backend is unconditionally replaced — frontend feature flag can't roll back.** Plan says both "REPLACE" and "KEEP chat endpoint" in the same line, and the chat streaming path is at regression risk.
   - **Fix**: Do **not** rewrite `platform/api/routers/insights.py`. Instead: (a) leave the existing Gemini chat endpoint untouched, (b) add the new endpoints (`/report/{ticker}`, `/report/{ticker}/refresh`, `/runs/{run_id}`, `/report/{ticker}/history`) as additional handlers in the same router module, (c) add unit tests that pin the existing chat endpoint's contract so any accidental change fails CI. Frontend flag `VITE_INSIGHTS_V2` can now fully roll back to chat-only without backend deploys.

5. **`ADMIN_TOKEN` through `VITE_*` leaks into the client bundle.** Any browser visitor can extract it from JS.
   - **Fix**: Drop all `VITE_ADMIN_*` env vars. Admin auth becomes a server-only check: the FastAPI admin router validates a header token against `ADMIN_TOKEN` env on the server. The admin page calls `/api/admin/*` directly; the user supplies the token via a session input (stored in sessionStorage, not build-time env). Sidebar shows the Admin link unconditionally; the page itself refuses to render until a valid token is entered. v2 replaces this with proper OIDC.

### IMPORTANT

6. **`LLMClient.complete(response_schema=...)` papers over real divergence.** Vertex uses OpenAPI-subset `response_schema`; Anthropic uses tool-use forced-choice (no native schema, tuple types don't express well); OpenAI Structured Outputs is strict and rejects some `Literal`/default combos.
   - **Fix**: The `LLMClient` interface takes a Pydantic model, not a raw JSON schema. Each adapter translates: Vertex adapter uses `response_schema` from `model_json_schema()`; Anthropic adapter wraps the schema as a `tools=[{"input_schema": ...}]` forced-tool-call and unwraps the tool input; OpenAI adapter uses `response_format={"type": "json_schema", "strict": True}`. `tuple[float, float]` in `InsightReport.entry_zone` is replaced with a `EntryZone(BaseModel): low: float; high: float` to be safe across all three. Every adapter has its own unit test against a recorded fixture response.

7. **Prompt caching savings are overstated.** Gemini context caching needs ≥32k tokens; Anthropic cache_control needs ≥1024/block with 5-min default TTL. The "~5×" number was wrong.
   - **Fix**: Delete the ~5× claim from the Cost section. Caching is best-effort per adapter: Vertex adapter skips caching unless the system+context block crosses 32k (not expected day-one); Anthropic adapter uses `cache_control` on the system block only. Realistic savings on Anthropic: ~2× on warm cache hits within a 5-minute window. Day-one Gemini: zero caching benefit, budget reflects this (it already does — ~$0.01–$0.03/run).

8. **Embedding model and backfill undefined.** `VECTOR(768)` is hard-coded but no embedder is named; existing journal entries have no embeddings.
   - **Fix**: Use Vertex `text-embedding-005` (768-dim, already on the same service account — no new secret). Add `lib/agents/embeddings.py` with `embed_text(text) -> list[float]`. Add `scripts/backfill_journal_embeddings.py` — run once before the pipeline depends on reflection memory. Added to verification step 2.5.

9. **Model route lookup inconsistency mid-run.** 60s cache + 30s pipeline run = admin change mid-run produces split `model_versions`.
   - **Fix**: Snapshot all 7 routes **once at pipeline start** (`routes = load_routes_snapshot()`), pass the dict into every node. The 60s cache is only used by the first call of each new pipeline run. `model_versions` in the report is always consistent.

10. **Stale upstream data.** `premarket_analysis` is from 8:30 AM ET; a 4:30 PM ET report reads 8-hour-old strat state.
    - **Fix**: Move the scheduled workflow to `30 12 * * 1-5` (8:30 AM ET), running **after** the existing premarket brief workflow completes — use `workflow_run` trigger on `premarket-brief.yml` success (or cron with a 15-min offset if that workflow doesn't exist). Also: `summarize_strat_status` re-computes strat state live from `market_data_daily` instead of reading `premarket_analysis` — no dependency on upstream freshness. The premarket brief remains a *bonus* input (not the source of truth).

11. **No circuit breaker; one analyst failure kills the run.** `asyncio.gather` raises on first exception.
    - **Fix**: Use `asyncio.gather(*tasks, return_exceptions=True)`. Each analyst result is either `AnalystOutput` or an `Exception`; failed analysts are logged, marked `status='failed'` in the InsightReport's `failed_sections[]`, and downstream agents continue with what's available. Report still publishes but clearly marks the degradation. Pipeline fails hard only if the trader or portfolio_manager fails.

12. **`asyncio.gather` with sync `google-genai`.** Without `asyncio.to_thread`, no real parallelism.
    - **Fix**: Every adapter's `complete()` is `async def` and wraps sync SDK calls in `await asyncio.to_thread(...)`. Parallelism is achieved via the threadpool. This is stated explicitly in `lib/agents/llm_client.py` implementation notes.

13. **JSONB query performance.** Only a btree on `(ticker, as_of DESC)`.
    - **Fix**: Add `CREATE INDEX IF NOT EXISTS idx_insight_reports_report_gin ON insight_reports USING GIN (report jsonb_path_ops);` so the history view can filter by direction/conviction without scans.

14. **Downstream impacts unverified.** Nothing in the plan confirms which other files reference `InsightsPage.tsx`, `insights/chat`, or `useInsights*`.
    - **Fix**: First execution step (before any code change) is `grep -rn "insights" platform/src tests` + `grep -rn "from .insights\|routers.insights\|/api/insights" platform tests` and list every hit in a file-impact table in the PR description. Confirm Sidebar, App.tsx router, any E2E spec, and CLAUDE.md are updated or unaffected.

15. **Cost accounting normalizer is non-trivial.** Vertex/Anthropic/OpenAI usage fields differ; cache-read tokens are separated on some providers.
    - **Fix**: Each adapter returns a normalized `Usage(input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, cost_usd)` dataclass. Price table lives in `lib/agents/pricing.py` keyed by `(provider, model)`. Adapter test fixtures include a usage-parsing assertion per provider.
