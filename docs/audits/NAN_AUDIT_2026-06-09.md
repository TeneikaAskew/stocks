# Dataset-wide float8-NaN / NULL Audit — 2026-06-09

**Trigger:** user request after the DQ1 gamma/strat_features remediation — "any
other failed null values in the codebase and data tables? full listing." This
sweeps **every** `double precision`/`real` column in **all 81 tables** of the
Cloud SQL `trading` dataset for IEEE float8 NaN (the §3.7 silent-fallback bug
class: NaN stored where a SQL `NULL` belongs, invisible to `IS NULL`).

**Method:** generated one count query per table (`gcp/queries/nan_triage.sql`,
batched under the 32 KB Cloud Run env-var limit), each scanning all its float8
columns for `= 'NaN'::float8`. Per-column drill-down for the worst offenders.
Read-only via `./scripts/db_query_cr.sh`.

**Headline:** the columns fixed in DQ1 (`strat_features_{tf}` + `gamma_levels_eod`)
are confirmed **0 NaN**. But **20 other tables still hold float8-NaN**, the
largest being the **`strat_features_levels_{tf}`** sibling tables (the level-map
join surface) which were OUTSIDE the DQ1 scope.

All of the above are §3.7 violations in the strict sense (NaN, not NULL), but
they fall into three remediation tiers:

- **BUG (must fix):** the value is wrong/missing AND financial — the writer
  fabricated NaN where NULL belongs, OR a feature is 100% unpopulated.
- **warmup / sparse-expected:** the value is *legitimately* absent (indicator
  warmup, open position, undefined statistic). Still should be NULL not NaN, but
  it does not corrupt a present value. Fix = the same `_na_to_none` discipline at
  the writer.
- **expected-undefined:** e.g. `indicator_correlation.pearson` when a window has
  no variance — genuinely undefined; NULL is the correct representation.

## C. Formula / derivation + fix status (Deliverable A3)

Columns already remediated in DQ1 (verified 0 NaN post-backfill):

| Column | Formula / source | Fix |
|---|---|---|
| `ema_200` | `ewm(span=200,min_periods=200).mean()` (`lib/indicators.py`); `lib/config.py` lacked 200 | added 200 to per-build `IndicatorConfig.ema_periods` (`strat_data_builder.py`) |
| `realized_vol_z` | per-day rv `logret.groupby(bar_date).rolling(15).std()`; z over **cross-day** window w/ min_periods (`lib/indicators.realized_vol_zscore`) | within-day z-window → all-NaN on <60 bar/day TFs; widened cross-day; wired to shared helper |
| `flip_price`→`gamma_balance_price`, `distance_to_king/gate_pct` | `lib/gamma.compute_gamma_balance` (cumulative cross); `(close−min_king/gate_strike)/close·100` | NaN carrier was broken `bulk_copy_upsert` COPY path; fixed to pg8000 `COPY…STDIN` + per-chunk `_na_to_none_records` (`gcp/database.py`) |
| `gamma_regime`/`total_gex` | `regime=sign(total_gex)`; `total_gex=Σ(call−put)netΓ·spot²·0.01` | inverted label → `sign(total_gex)` + rebuild |

The systemic fix — `gcp/database.py:_na_to_none_records` (per-chunk NaN/NaT→None)
+ the pg8000 stream COPY — is the lever that makes ANY future rebuild of the
above tables write NULL instead of NaN. The **remaining** NaN in §A/§B are stale
rows written by the OLD broken writer; they clear on the next rebuild of each
table through the fixed `upsert_dataframe`/`bulk_copy_upsert`.
