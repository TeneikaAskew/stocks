# Accept the complete trusted generated inventory

The AV schema changes expose an existing contradiction: insert_blocks(counts=True) also regenerates relation totals and breakdowns outside marker bodies, while the existing feature allowance excludes them. This supersedes the previous approved contract without editing it. It retains its byte, scope, trust-boundary and real-gate acceptance obligations and adds only the existing renderer-owned substitutions and package-initialization safeguards.

## Design

Only the same three infrastructure documents are allowed. Use the unchanged trusted main renderer and unchanged committed snapshot. First validate marker identity/order/mode, clean bytes, plain-file tree and unchanged render inputs. Materialize committed head source blobs without git attributes into an isolated temporary tree, then seed these three output documents with their exact merge-base bytes. Thus merge-base prose, rather than authored head prose, is the input to insert_blocks(counts=True). Run the trusted renderer in the isolated child with the existing read fence and no head imports. Require each submitted head document to equal the entire expected rendered document byte for byte.

Existing substitutions are exactly the unchanged renderer RUNTIME_RELATION_COUNT, RELATION_BREAKDOWN and ASOF_LABELS. Do not broaden their shapes or snapshot semantics. A source schema change can update inventory and its existing prose counters. Arbitrary prose, newly introduced count/date patterns, review stamps, historical dates, headings and changed marker lines are refused. General prose citations remain outside this allowance. Errors, missing snapshot/renderer, unsafe paths/modes/attributes, changed initialization input or escaped reads fail closed with REQ-GOV-004.

Both scripts/__init__.py and scripts/maintenance/__init__.py are trusted process inputs. Protect their ownership before later trusted imports, and refuse either changing alongside generated documents. Retain the original raw-byte diff, feature-record scope, immutable-cache safety and child isolation contracts. No workflow, hook, snapshot, exporter or renderer implementation change belongs here. Preserve the actual gate hook/CLI in every test; no alternate compiled invocation harness. Four independent pre-push reviewers remain mandatory.

## File ownership

scripts/gate/spec_gate.py; tests/scripts/test_spec_gate.py; .claude/skills/product-delivery/SKILL.md (exact allowance wording only); the owned FEAT-CICD-001 catalog and traceability records; one ready implementation plan. Canonical requirement and this approved documentation contract must land before code implementing the expanded allowance. Existing renderer, snapshot, workflows and pinned files are unchanged.

Small explicit representative fixtures at the same four source paths retain every adversarial assertion. Whole-tree rendering and unchanged neighbor suites independently cover production inputs.
