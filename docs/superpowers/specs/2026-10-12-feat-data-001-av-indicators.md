# Restore AV indicator contracts, UTC alignment and bounded refresh

## Authorization and intake

This records the scope of the six-stage remediation plan presented after the live AV/GCP audit and authorized by the user on 2026-10-12: "Proceed with the plan, executing inn parallel". Execution method: parallel isolated worktrees, one author and PR per plan. Capability: FEAT-DATA-001, whose catalog row defines "Ingestion, storage, freshness" and owns fetcher jobs, gcp/fetchers/ and gcp/schema.sql. This is the separate AV-indicator ingestion spec/plan, not the broader data-platform remediation spec. Issue #919 is touched because this restores its unfed market_data_indicators table; it is not closed because other unfed tables remain outside this stream. FEAT-IND-001's application indicator stack in lib/indicators.py and lib/signals.py is unchanged.

## Problem

ADOSC is entirely NULL because the parser expects Chaikin A/D instead of ADOSC. Intraday Eastern timestamps are labeled UTC. The stored daily and 15-minute history stops May 27 and May 26; the fetcher is unscheduled and lacks per-month history.

## Non-goals

No expansion to all 128 APIs, change to strategy/model promotion or risk calibration, fabricated financial values, blind rewrite of historical timestamps, unrelated IAM/audience changes, or unbounded backfill. API failures and historical-only exclusions remain explicit.

## Approaches considered

1. Targeted contract repair, independent reviewed streams, bounded source-backed repair and selective deployment — chosen to preserve the verified working paths.
2. Replace the complete ingestion platform — excessive scope and operational risk.
3. Change schedules without repairing data contracts — leaves the demonstrated corruption and observability gaps.

## Design

Fetch ADX, MFI, ADOSC, AROON, ROC and BBANDS using exact response keys and strict complete-group validation. Keep daily date keys at midnight UTC, convert intraday Eastern wall stamps with the shared DST-aware helper. Add bounded incremental and date/month backfill modes with explicit max-months, conservative pacing, per-group telemetry and nonzero incomplete exit. Persist only known per-function values to prevent warmup or partial-response NULL overwrites. Legacy timestamp replacement is an explicit repair mode: verify non-ADOSC existing values against newly fetched monthly vendor data, verify unchanged source rows in the transaction, and reuse the existing bounded atomic replacement utility. Refuse revised/unverifiable histories rather than delete guesses. Scheduled interface: --all --intervals=daily,15min --mode=incremental --lookback-days=7 --max-months=2.

An incremental run covers seven inclusive calendar dates ending yesterday on the Eastern clock: start=end minus six days. --max-months caps the distinct intraday request months before network or persistence begins. Backfill --start-date and --end-date are inclusive, mandatory, and limited to at most three distinct months per invocation; larger scopes fail explicitly and are split into independent rerunnable invocations. A successful empty selection is no_data only when the requested window contains no NYSE sessions; an empty or incomplete response for a window requiring session observations is error. Validate the group before any of its six function writes, retain previously durable complete groups after a later failure, and report partial/error rather than a false success.

### Strict vendor identity and time metadata

Validate metadata before labeling rows or converting any timestamp. The actual audit fixtures at work/av_audit/actual_ind_* contain a Meta Data object with 1: Symbol, 2: Indicator, 3: Last Refreshed and 4: Interval. Symbol must match the requested normalized ticker, interval must exactly equal daily or 15min as requested, and the Technical Analysis: <function> key and indicator label must both match the requested function's recorded contract. Actual labels are Average Directional Movement Index (ADX), Money Flow Index (MFI), Chaikin A/D Oscillator (ADOSC), Aroon (AROON), Rate of change : ((price/prevPrice)-1)*100 for ROC, and Bollinger Bands (BBANDS). ROC metadata does not contain the token (ROC); do not invent that label. Reject missing, contradictory or unsupported metadata and malformed last-refreshed dates rather than converting/assigning the requested identity regardless of the response.

The timezone field is function-specific: 6: Time Zone for ADX/MFI/ADOSC/AROON, 7: Time Zone for ROC and 8: Time Zone for BBANDS. All captured daily and 15min indicator fixtures report US/Eastern Time. Validate that field against the explicit Eastern-label allowlist US/Eastern Time, US/Eastern and America/New_York, canonicalized to the shared America/New_York zone; UTC and fixed EST/EDT labels are rejected. Daily metadata still carries an Eastern timezone even though its payload keys are business dates stored at UTC midnight. These keys and labels differ from TIME_SERIES_INTRADAY OHLC metadata (which uses 2. Symbol and US/Eastern); do not reuse that schema accidentally. tests/gcp/test_fetch_av_indicators.py::test_vendor_metadata_rejected_before_conversion parametrizes wrong/missing symbol, interval, indicator, function payload key and timezone for both intervals and asserts the conversion/persistence boundaries were never called. Recorded successful metadata fixtures cover all six functions and both intervals.

Calculation metadata must also agree with the immutable configuration: 5: Time Period is 14 for ADX/MFI/AROON, 10 for ROC and 20 for BBANDS; ADOSC's actual keys 5.1: FastK Period and 5.2: SlowK Period are 3 and 10; ROC uses 6: Series Type=close; BBANDS uses 7: Series Type=close, 6.1: Deviation multiplier for upper band=2, 6.2: Deviation multiplier for lower band=2 and 6.3: MA Type=0. ### Complete regular-session timestamp coverage

Expose one source-backed 15-minute session-grid contract shared by ingestion and OPS: a NYSE session's actual open is inclusive and actual close exclusive, with timestamps labeling interval starts. A normal 09:30-16:00 Eastern session requires exactly the 26 start labels 09:30, 09:45, ..., 15:45; a 09:30-13:00 half-day requires the 14 labels through 12:45. Convert each exchange-calendar instant to UTC through the shared DST-aware boundary. For every NYSE session within the requested date window, each of the six function responses must contain finite known values for its required vendor fields at every required grid timestamp. Compare exact timestamps, not total counts, date maxima or intersection of six equally truncated responses. A wrong-phase grid, omitted opening/closing slot or interior gap fails the group before journal/cache writes. Legitimate additional premarket, closing-instant or after-hours rows are retained and allowed, but cannot substitute for required regular-session rows. Daily requires all requested NYSE session dates. A calendar failure is explicit error; never approximate away required coverage.

The convention is verified from actual sources: the newly captured IWM TIME_SERIES_INTRADAY 15min observation at 2026-10-09 09:30 has OHLC 278.21/278.86/277.71/277.795, exactly matching archived one-minute OHLC aggregated over 09:30 through 09:44 rather than 09:16 through 09:30. Recorded indicator fixtures contain these same start-label timestamps. The captured ADOSC 2025-11 response for the November 28 half-day contains all 14 required labels plus 13:00 and extended-hour extras. Preserve these metadata/label evidence fixtures in the implementation tests, with source parameters/retrieval/hash and a concise provenance note. tests/gcp/test_fetch_av_indicators.py::test_session_grid_rejects_truncated_complete_fields removes the same late-session portion from all six otherwise valid responses and asserts error/nonzero with no writes for that group. ::test_halfday_start_label_grid checks 14 required half-day slots, allows extras and rejects an interior missing slot. ### Price basis and corporate actions

The [AV technical-indicator documentation](https://www.alphavantage.co/documentation/#technical-indicators), checked 2026-10-12, states: "All indicators are calculated from adjusted time series data to eliminate artificial price/volume perturbations from historical split and dividend events." Therefore all six functions retain AV's adjusted vendor values in both intervals. Store explicit interval-specific metadata: daily uses price_basis=av_adjusted_daily, corporate_action_policy=vendor_split_dividend_adjusted, interval=daily; 15min uses price_basis=av_adjusted_intraday, corporate_action_policy=vendor_split_dividend_adjusted, interval=15min. Record the vendor's own interval/timezone metadata, the policy/version identifier and the documentation reference alongside the safe request parameters, and include the basis/policy in the configuration hash. These indicator endpoints have no supported adjusted=false switch; do not invent one or substitute locally recomputed indicators. Journal retrieval time identifies which vendor revision was knowable, including later corporate-action revisions.

As-of selection requires the caller's expected interval, configuration hashes and price basis; it rejects incompatible raw, unknown or differently adjusted basis rather than silently joining to the downstream magnitude dataset. Daily raw OHLC fields from TIME_SERIES_DAILY_ADJUSTED do not become adjusted merely because the endpoint also returns adjusted_close. Downstream model promotion remains outside this spec, and no experiment is declared compatible unless its price-basis contract matches. A frozen synthetic two-for-one split fixture includes raw closes 100 before/50 after and vendor-adjusted closes 50/50, plus explicitly labeled synthetic AV-shaped indicator responses. It proves that the supplied values and basis survive ingestion and revision retrieval, and that a raw-price or wrong-interval basis request fails explicitly. The fixture tests compatibility, not local calculation of an AV replacement or a claim of live vendor reconciliation.

### Capacity and cost

Three tickers, six functions, daily plus at most two intraday months => at most 54 calls and <=72 bounded function-group write chunks. This absolute bound includes every attempted call: application/adapter retries are prohibited. Estimate <=350 seconds with shared-key conservative pacing and pg8000 round trips; one CPU, 512 MiB and 1,800-second timeout, zero task retries. Peak one ticker/function/month plus ~7,000 daily records, under tens of MiB. Historical depth is sharded <=3 months per invocation, never an unlimited one-task 25-year backfill. Incremental journal upper bound 8,190 rows x ~600 bytes =~4.9 MB/run (~147 MB per 30 daily runs before indexes); retain one round trip per chunk to keep the <=350-second estimate. Historical journal chunks remain bounded; a 63-session three-month/core-three shard is <=73,710 observations x ~600 bytes =~44.2 MB durable journal input, processed one function/month/chunk at a time.

Cloud Run Jobs estimate, excluding free-tier discounts: 350 billed seconds x (1 vCPU x $0.000018/vCPU-second + 0.5 GiB x $0.000002/GiB-second) = $0.00665/run. Tuesday-Saturday cadence is 5/7 runs/day on average: $0.00665/run x (5/7 runs/day) x 30 = $0.1425/month. A conservative daily-run budget is $0.00665 x 1 x 30 = $0.1995/month. This excludes the existing AV subscription: no new per-call vendor charge is assumed within its entitlement; any plan upgrade must be explicitly costed before rollout. Separately budget up to $0.10/month for an additional Cloud Scheduler job outside its free allowance. Cloud SQL is already provisioned, so queries incur no separate per-query bill; journal growth is retained history, approximately 1.8 GB/year before indexes at the conservative daily ceiling, and allocated storage/autogrowth plus index overhead must be measured in rollout evidence rather than represented as zero storage forever. Confirm regional billing rates and measured billed duration in the deployment PR.

Phase 2 is an on-demand consumer, not an additional scheduled job. Its temporal read is limited to one ticker, daily interval, at most three months per explicit slice and a conservative absolute 40,000-bar input cap; actual session counts come from the shared calendar. Each slice is one query with at most six function/configuration branches, <=40,000 returned bar rows x ~600 bytes including known fields and source references (~24 MB), and indexed retrieval eligibility; no additional AV/archive calls. More rows or longer ranges fail explicitly before SQL. Production EXPLAIN and meaningful 20,000-journal-row/query-shape fixtures verify bounded work without one network call per bar; at the production driver estimate the single query contributes one 0.5-2s round trip plus measured indexed server work. A 40,000-cutoff local PostgreSQL shape/latency fixture records actual rows, server time and buffers; require <=30 seconds per slice for its measured query plus conversion at smoke workload before admitting that bound.
