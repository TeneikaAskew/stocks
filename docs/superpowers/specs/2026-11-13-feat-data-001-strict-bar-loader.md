# A strict 1-minute bar read for replays and backtests

## Problem

The owner's rule, 2026-11-13: every replay and backtest reads 1-minute bars only from `market_data_intraday` (interval `1min`), the Cloud SQL table the nightly pull fills. None fetches bars itself or takes them from anywhere else. When the table lacks the ticker or the window, the run says so. Scope is SPY, QQQ and IWM. Read at `main` c698b24e, with the runs of 2026-11-13 kept in the two scratch folders named under Design 8:

- The shared loader substitutes other data and does not tell its caller.
  - `DataLoader.load_intraday` reads the table (`lib/data_loader.py:377-380`), then local parquet when the result is empty (`:382-412`).
  - The table read goes through `_query_cloud_sql`, which logs and returns an empty frame on any error (`:188-224`). An outage and an empty window look the same.
  - `load_best_available` then falls back to daily bars (`:653-674`). Run: with `get_engine` raising `ConnectionError`, `load_intraday` returned an empty frame and raised nothing, and `load_best_available` returned the two daily bars it was given.
  - `_cloud_sql_active` checks only `CLOUD_SQL_CONNECTION_NAME` (`:146-148`). Run: with only `DB_HOST`, `DB_USER`, `DB_PASS` and `DB_NAME` set, `gcp.database.is_cloud_sql_configured()` was True (`gcp/database.py:49-67`) and the loader made zero queries.
- The job image has no `data/` directory (`gcp/Dockerfile:20-23` copies `lib/`, `gcp/`, `scripts/` and one config file; `.dockerignore:5` drops `/data/`). So in Cloud Run the real effects are two: an outage reads as "no bars", and a backtest for a ticker with daily rows and no 1-min rows runs on daily bars and reports its numbers.
- Ten call sites on a replay or backtest path use the non-strict loader. Design 2 lists them.
- The `backtest` job gives an outage and a defect the same answer, with the driver's text in it. Run: `gcp.backtest_job.run()` posted `Backtest crashed for AMD: connection refused 10.0.0.5:5432` for a `ConnectionError` and `Backtest crashed for AMD: 'close'` for a `KeyError` (`gcp/backtest_job.py:133-138`).
- `POST /api/style/mine-and-validate` validates a mined profile on whatever frame the loader hands back and stages the result (`platform/api/routers/backtest.py:620-638`, `:778-783`, `:801`, `:843`, `:873`).
- The end-of-day resolver cannot tell an outage from a missing day, and says so in its own comment (`gcp/signal_monitor_eod_resolver.py:211-219`). It works around it with a control read (`:226-239`).
- `phase6-playbook` prints `No data, skipping.` and exits 0 when a ticker has no bars (`scripts/analysis/phase6_playbook.py:1058-1060`).
- Seven bar reads leave out the interval. The column's comment lists five intervals (`gcp/schema.sql:142`) and the key and the index both lead with `(ticker, interval, ts)` (`:152`, `:167-168`).
  - Three name no interval at all: `scripts/validation/validate_brief_accuracy.py:185-190`, `gcp/historical_signals.py:314-323` and `gcp/signal_monitor.py:1997-2006`.

Each means 1-min bars: its docstring says so (`gcp/build_intraday_gex.py:93`, `gcp/build_realtime_gex.py:87`, `lib/features/intraday_flow.py:113-115`), or the fetch it guards does (`scripts/backfill_watchlist_data.py:256`).
  - Run on a local Postgres 16 that held only this table (its DDL cut from `gcp/schema.sql`), through the real functions, with a `1min` row at 14:00 UTC (close 100) and a `5min` row at 14:05 UTC (close 555): `_session_bars` and `load_intraday_bars` returned both bars; both `_load_intraday_spots` gave the 14:00 bucket a spot of 555; `_load_ofi_buckets` counted 2 minutes in that bucket; and `needs_intraday_backfill` was False for a ticker whose only recent row was a `5min` one.

## Approaches considered

1. A separate strict method that raises typed errors, called by every replay and backtest entry point, with the default left alone (chosen). The non-replay callers and the parquet tests are untouched, and a guard can ban the non-strict names from replay paths.
2. Change the default of `load_intraday` to strict. Rejected: it breaks the local research scripts and the parquet tests in the same PR.
3. A `strict=True` keyword on `load_intraday`. Rejected: the test fakes of the research jobs accept any keyword (`tests/gcp/test_indicator_correlation_job.py:132`), so a caller that forgot it would still pass its tests.

## Design

### 1. The strict loader (`lib/data_loader.py`)

```python
class IntradayBarsNotInStore(LookupError):
    def __init__(self, ticker: str, start_date: Optional[str] = None,
                 end_date: Optional[str] = None, *, regular_hours: bool = False)
    # .ticker: str   .start_date, .end_date: Optional[str]   .regular_hours: bool
class IntradayStoreNotConfigured(RuntimeError):

def coverage_note(df: pd.DataFrame, ticker: str, start_date: Optional[str] = None,
                  end_date: Optional[str] = None) -> Optional[str]

class DataLoader:
    def load_intraday_strict(self, ticker: str, start_date: Optional[str] = None,
                             end_date: Optional[str] = None, *,
                             max_age_days: int = 2, on_stale: str = 'silent') -> pd.DataFrame
```

- It reads only `market_data_intraday` with `interval = '1min'`, through `gcp.database.query_to_dataframe_strict`.
- `_load_intraday_from_sql` (`:426-482`) gains a `query=None` parameter. `None` means the module's `_query_cloud_sql`, looked up when the call runs, so the tests that monkeypatch it keep working (`tests/lib/test_data_loader.py:641`, `:681`). The strict method passes a function that calls `query_to_dataframe_strict`. Both paths share the SQL, the window rule and the Eastern conversion.
- The interval moves from a bound parameter into the text of the f-string itself (`:443-444`, `:454-459`): `WHERE ticker = :ticker AND interval = '1min'`, with only the optional `ts` bounds interpolated. The interval guard of Design 7 reads an f-string's constant parts, so the words have to be there.
- It returns what the table branch of `load_intraday` returns: a naive Eastern `Time` index, columns `Open High Low Close Volume Time`, the same `attrs` defaults (`:421-423`) and the same staleness check (`:418-420`).
- No bars: `IntradayBarsNotInStore`. That covers zero rows from the query and rows that the Eastern cut drops entirely (`:472-478`; run: one stored row outside the window left an empty frame). It never returns an empty frame.

### 7. The interval guard (`tests/meta/test_production_writers.py`)
