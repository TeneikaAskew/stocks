# Make source-review fixture plans independent of completed delivery plans

## Problem and ownership

CHANGE under FEAT-CICD-001, whose catalog capability is Build, test, deploy automation / CI testing. The canonical path is `docs/superpowers/specs/2026-10-23-feat-cicd-001-source-plan-fixture-lifecycle.md`. This is a complementary contract: it retires or amends none of the approved verifier, policy, inventory or capacity contracts.

Historical failure evidence: full test job120297270745 on the original PR1568 failed when postmerge documentation close-out set the canonical1470 plan to done. `test_actual_declared_note_preflight_then_bound_record` copies that real plan from ROOT and assumes it is still ready. Completing the real plan therefore makes a synthetic active feature fixture ineligible. A temporary terminal marker/sidecar close-out may preserve the real plans' current ready status, but cannot claim their final status-only completion or repair this test dependency. Accepting a production done plan would be incorrect.

Ten current reads in `tests/scripts/test_doc_source_snapshot.py` copy that canonical plan: the Repo constructor, bound_note_repo, the declared-note accepted control, the malformed-declaration negative control, oversized trusted-policy inputs, repeated-spec-byte accounting, policy_batch_repo, the full current-SITE body control, complex_body_repo and the additive-watcher control. Fixing only the first constructor leaves later copies coupled to the completed plan. An invalid fixture can also make an intended negative case pass for the wrong reason.

The source-review verifier remains correct to require exactly one valid committed ready binding for an active named feature branch. Its unchanged specification and implementation, especially selected_binding, continue to govern acceptance. The real canonical plans retain their actual current lifecycle. They remain ready while their separate status close-out is pending and become done only through genuine later postmerge DOC work; a fixture must require neither state from those real files.

## Design

Confine executable changes to `tests/scripts/test_doc_source_snapshot.py`. Use one explicit deterministic test-fixture plan constructor and route all ten canonical-plan copy sites through it. The constructor supplies the existing fixture's actual FEAT, branch, PR7, selected approved spec and valid task-body metadata, including ready as an explicit fixture state. Cases selecting the approved note-bearing fixture spec retain that selection. Fixture construction must not read the real canonical plan's lifecycle or mutate the real plan to make a test pass. It must remain possible for a test to deliberately commit a non-ready fixture plan as a negative input.

Preserve every current test name, meaningful assertion and case, actual Git/producer/verifier/auditor/gate invocation, and the intended assertion failure class. Do not replace real CLIs with success dictionaries, swallow assertions, weaken a negative to an unrelated invalid-plan failure, skip tests or reinterpret expected verdicts. In particular, leave deliberate oversized selected-plan mutation of repo.path/PLAN, oversized spec/registry inputs, malformed declarations, competing bindings, object formats and source-identity predicates intact. Changes are fixture construction plus the three named coverage/lifecycle regressions, not a production binding change.

The named coverage regression `test_fixture_plan_constructor_covers_all_consumers` must enforce the complete ten current consumers, not only the declared-note accepted path. Its independently specified consumer inventory is: Repo.__init__, bound_note_repo, test_actual_declared_note_preflight_then_bound_record, test_actual_no_or_malformed_declaration_cannot_clear_code_drift, test_actual_oversized_trusted_policy_inputs_refuse_before_content_read, test_actual_repeated_baseline_policy_source_spec_bytes_all_count, policy_batch_repo, test_actual_full_current_site_producer_hash_matches_complete_original_normalizer, complex_body_repo and test_actual_minimum_preserves_additive_watchers. The four note-spec consumers retain NOTE_SPEC; the others retain SPEC. Check their actual test-source AST or execute every consumer under a done canonical input, and validate the constructed plans' explicit FEAT, branch, PR7, ready lifecycle, spec choice and valid task body against the unchanged plan contract. Static coverage must reject an omitted consumer, a remaining direct canonical-plan acquisition in fixture construction or a wrong fixture spec, rather than merely count a disconnected list. Deliberate inspection of temporary canonical inputs inside the lifecycle regression is permitted; it is not fixture construction. Prove RED on pre-fix MAIN and refusal of every partial nine-of-ten conversion, including leaving a copy in a negative or budget test; a structurally complete control must pass. Such static coverage is additional to the real CLI behavior below, never a substitute for it.

The canonical-lifecycle regression supplies actual temporary ready and done canonical inputs alongside the same trusted production code, then exercises the real declared-note accepted sequence for both SHA-1 and SHA-256. It proves that the fixture's explicit ready metadata is independent of those temporary inputs and that the actual canonical plan's bytes and current status are untouched. Actual MAIN at this specification's parent has the canonical1470 plan ready; the implementation must not falsely claim it is already done. The eventual legacy plan-status close-out follows the fixture CODE merge. Preserve preflight's real initial refusal before a note is bound and successful production only after a genuine committed matching note.

The non-ready regression deliberately commits only the fixture plan's active status transition and uses otherwise matching accepted ready controls. The real producer/verifier and PR gate must refuse the invalid active binding where their existing contract requires it; no note, record kind, caller flag or fixture builder may convert that done plan into a ready production input. Preserve failed-production atomic output behavior. This is separate from legitimate landed record verification and postmerge done-plan semantics; the test must use an actual active feature branch with changed source rather than label a landed trunk record invalid merely because its historical plan is done.
