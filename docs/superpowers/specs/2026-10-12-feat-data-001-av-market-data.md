# Preserve AV daily adjustments and ingest selected reference endpoints

## Authorization and intake

This records the scope of the six-stage remediation plan presented after the live AV/GCP audit and authorized by the user on 2026-10-12: "Proceed with the plan, executing inn parallel". Execution method: parallel isolated worktrees, one author and PR per capability. Capability: FEAT-DATA-001; matching catalog row in docs/product/02-FEATURE-CATALOG.md. The listed issues are touched, not claimed closed without their own acceptance evidence.

## Problem

The production audit found 12,628 of 12,930 AV daily rows for October 5–9 without adjusted_close. The broad daily parser requests TIME_SERIES_DAILY_ADJUSTED but drops its adjusted close. INDEX_DATA and INDEX_CATALOG work with the production key, while no native index ingestion exists. Selected metadata endpoints have no ingestion contract.

## Non-goals

No expansion to all 128 APIs, change to strategy/model promotion or risk calibration, fabricated financial values, blind rewrite of historical timestamps, unrelated IAM/audience changes, or unbounded backfill. API failures and historical-only exclusions remain explicit.

## Approaches considered

1. Targeted contract repair, independent reviewed streams, bounded source-backed repair and selective deployment — chosen to preserve the verified working paths.
2. Replace the complete ingestion platform — excessive scope and operational risk.
3. Change schedules without repairing data contracts — leaves the demonstrated corruption and observability gaps.

## Design

Preserve adjusted_close in every AV daily writer. Add a bounded explicit-ticker/date repair that updates existing rows only, defaults to a reviewable dry-run, and commits per ticker with idempotent batch SQL. Add native SPX and VIX daily index routing preserving the existing ^VIX stored alias, raw OHLC and absent volume as NULL; retain explicit AV index provenance and reject silent Yahoo fallback. Add bounded INDEX_CATALOG, INDEX_DATA, ETF_PROFILE, DIVIDENDS, SPLITS and LISTING_STATUS ingestion using actual vendor contracts. Store normalized reference records and safe request/raw response/fetched UTC/SHA256 provenance in an additive SQL journal; limit journal retention to 90 days. Produce a 128-function registry with parameters, entitlement, symbol scope, timezone, table/key, cadence, owner, retained fields and excluded/historical-only reasons. Planned endpoint status is not called active until deployment evidence exists. Broad daily backfill and repair publish complete/partial/error counts and fail nonzero for failed requested groups. Registry format is version 1 with a functions mapping; lifecycle is one of active, planned, on_demand, historical_only or excluded, and keys are validated against declared table contracts. No imports from an unmerged sibling branch.

### Raw versus adjusted consumer policy

Canonical stored OHLCV remains as traded for session levels, option strikes and execution. Continuous daily returns, indicators and dimensionless cross-session STRAT labels/combos/FTFC use all OHLC consistently scaled by adjusted_close/close, never Close alone. Preserve canonical stored volume as traded, but build analysis Volume using cumulative split coefficients alone: for target basis date b, analysis_volume(t)=raw_volume(t) x product(split_coefficient(d), t<d<=b). A two-for-one split with 100 old shares and 200 new shares becomes 200/200 analysis shares; a dividend with no split leaves Volume unchanged. Never derive this volume factor from adjusted_close/close because that includes dividends. Retain required positive `split_coefficient` from AV daily field `8. split coefficient` in all relevant daily fetch/backfill paths and additive market_data_daily.split_coefficient DOUBLE PRECISION; indices use verified coefficient=1. Missing/unverified coefficient history makes split-sensitive RVOL/OBV unavailable, never assumes one. For a regeneration window, process price/volume on the same declared target-basis date; convert price-dimensional outputs to row raw-price units and share-dimensional OBV/volume averages back to that row's share basis using the independent split factor. Dimensionless RVOL stays continuous. Golden fixtures include split price 200/100 plus raw volume 100/200, and a dividend-only price adjustment whose volume factor remains one. `lib/price_basis.py` validates finite positive price and split factors, prepares adjusted daily price/analysis-volume frames and restores price-dimensional EMA/SMA/ATR/MACD/Bollinger and actionable STRAT trigger levels to the current row's raw units. Daily call sites in the live writer and historical indicator backfill invoke existing `lib.strat.StratClassifier` on adjusted frames; the generic classifier and intraday strategy fixtures stay unchanged. Previous-session executable levels remain explicit raw observations; a multi-bar structural trigger calculated in adjusted history is divided by the target session's validated factor, rather than taken from an unadjusted previous-session bar across a split. Tests compare labels and combos to an equivalent no-action continuous fixture, and verify that converted trigger levels match the target session's price units.

The daily loader defaults to `price_basis='raw'` for execution/levels and exposes `price_basis='adjusted'` only with explicit current-use semantics. Price-dimensional enrichment columns are rescaled consistently. Add `market_data_daily.indicator_basis_version TEXT`, `indicator_pipeline TEXT`, `indicator_artifact_id UUID` and `indicator_provenance JSONB`. Version `av-adjusted-daily-v1` covers the new continuous metrics and structural labels. Existing non-NULL enrichment is legacy: adjusted reads reject the legacy version and incomplete provenance until full-context regeneration recomputes it. Gap selection includes legacy-version rows even when all numeric fields are populated, with a maximum 50 tickers per run. Recent-window refresh certifies only rows it actually regenerates; older history remains legacy. A raw-close 200,100 split fixture must regenerate SMA2=100, not reinterpret legacy SMA2=150. No version is stamped on failed, skipped or partially calculated groups.

Historical/replay adjusted reads fail closed unless an immutable input vintage was recorded no later than the requested `as_of` and all required bars and enrichment can be selected from that same vintage. A mutable latest cache or a journal fetched after `as_of` never qualifies. This change does not implement a historical vintage reader: adjusted PIT/replay mode rejects year-scoped/historical requests, explicit past `as_of`, replay flags (`REPLAY_DATE`, `BRIEF_AS_OF`, `INSIGHT_AS_OF`) and attempts to use the current cache as an immutable artifact. An explicitly current_revision_analytics request may use a bounded historical/year selection on today's coherent revision, with the actual input observation clock retained; this is refused by replay consumers and does not certify historical strategies. Regression tests place a later split revision behind an earlier as-of clock and require rejection. Raw historical/replay reads apply the daily source-revision gate below before any date filtering or fallback; legacy source availability remains explicitly unverified, and #913 is touched without claiming complete historical corporate-action accounting.
