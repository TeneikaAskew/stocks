# Preserve AV daily adjustments and ingest selected reference endpoints

## Authorization and intake

This records the scope of the six-stage remediation plan presented after the live AV/GCP audit and authorized by the user on 2026-10-12: "Proceed with the plan, executing inn parallel". Execution method: parallel isolated worktrees, one author and PR per capability. Capability: FEAT-DATA-001; matching catalog row in docs/product/02-FEATURE-CATALOG.md. The listed issues are touched, not claimed closed without their own acceptance evidence.

## Problem

The production audit found 12,628 of 12,930 AV daily rows for October 5–9 without adjusted_close. The broad daily parser requests TIME_SERIES_DAILY_ADJUSTED but drops its adjusted close. INDEX_DATA and INDEX_CATALOG work with the production key, while no native index ingestion exists. Selected metadata endpoints have no ingestion contract.

## Non-goals

No expansion to all 128 APIs, change to strategy/model promotion or risk calibration, fabricated financial values, blind rewrite of historical timestamps, unrelated IAM/audience changes, or unbounded backfill. API failures and historical-only exclusions remain explicit.

## Approaches considered

1. Targeted contract repair, independent reviewed streams, bounded source-backed repair and selective deployment — chosen to preserve the verified working paths.
2. Replace the complete ingestion platform — excessive scope and operational risk.
3. Change schedules without repairing data contracts — leaves the demonstrated corruption and observability gaps.

## Design

Preserve adjusted_close in every AV daily writer. Add a bounded explicit-ticker/date repair that updates existing rows only, defaults to a reviewable dry-run, and commits per ticker with idempotent batch SQL. Assign scheduled native SPX and VIX daily publication exclusively to the dedicated index/catalog job, preserving the existing ^VIX stored alias, raw OHLC and absent volume as NULL; retain explicit AV index provenance and reject silent Yahoo fallback. Add bounded INDEX_CATALOG, INDEX_DATA, ETF_PROFILE, DIVIDENDS, SPLITS and LISTING_STATUS ingestion using actual vendor contracts. Store normalized reference records and safe request/raw response/fetched UTC/SHA256 provenance in an additive SQL journal; limit journal retention to 90 days. Produce a 128-function registry with parameters, entitlement, symbol scope, timezone, table/key, cadence, owner, retained fields and excluded/historical-only reasons. Planned endpoint status is not called active until deployment evidence exists. Broad daily backfill and repair publish complete/partial/error counts and fail nonzero for failed requested groups. Registry format is version 1 with a functions mapping; lifecycle is one of active, planned, on_demand, historical_only or excluded, and keys are validated against declared table contracts. No imports from an unmerged sibling branch.

### Raw versus adjusted consumer policy

Continuous daily returns, indicators and dimensionless cross-session STRAT labels/combos/FTFC use all OHLC consistently scaled by adjusted_close/close, never Close alone.
