# Make AV audit completeness and field coverage observable

## Authorization and intake

This records the scope of the six-stage remediation plan presented after the live AV/GCP audit and authorized by the user on 2026-10-12: "Proceed with the plan, executing inn parallel". Execution method: parallel isolated worktrees, one author and PR per capability. Capability: FEAT-OPS-001; matching catalog row in docs/product/02-FEATURE-CATALOG.md. The listed issues are touched, not claimed closed without their own acceptance evidence.

## Problem

audit-infra-drift cannot list scheduler jobs but exits zero and reports no findings. Strict freshness can pass unknown check results, and several reads swallow database errors. Required adjusted-close/AV-indicator fields have no complete coverage check.

## Non-goals

No expansion to all 128 APIs, change to strategy/model promotion or risk calibration, fabricated financial values, blind rewrite of historical timestamps, unrelated IAM/audience changes, or unbounded backfill. API failures and historical-only exclusions remain explicit.

## Approaches considered

1. Targeted contract repair, independent reviewed streams, bounded source-backed repair and selective deployment — chosen to preserve the verified working paths.
2. Replace the complete ingestion platform — excessive scope and operational risk.
3. Change schedules without repairing data contracts — leaves the demonstrated corruption and observability gaps.

## Design

### Audit outcomes and strict queries

Infrastructure checks that cannot execute are incomplete, not a no-findings success. Exit 2 for incomplete checks or failed alert delivery; ordinary completed drift findings retain exit 0 to avoid treating a detected drift item as an execution error. Use strict SQL with explicit server-side timeouts in every freshness query path currently capable of swallowing database failures. Emit an attributable unknown check on a database error; do not silently skip a required missing table, column or result. Strict freshness exits 2 whenever any unknown result or an empty report exists, even when aggregate display status is warn or stale; otherwise stale exits 1 and a completed non-stale report exits 0. Preserve existing aggregate display semantics for callers. No new overlapping UI freshness implementation.

### Raw-versus-adjusted policy ownership

The adjusted-close detector measures vendor-field presence only. It does not certify corporate-action correctness, consumer selection of raw versus adjusted prices, indicator parity, or replay semantics. That policy and its split/dividend consumer/parity evidence belong to FEAT-DATA-001/#913 under the approved dependency `docs/superpowers/specs/2026-10-12-feat-data-001-av-market-data.md`. Link its exact merged revision and policy evidence in the operations runbook; do not describe a green presence check as completion of #913 or REQ-DATA-004's price-policy requirement. REQ-DATA-004 in this OPS spec serves the exchange-calendar contract below.

Check existing settled daily rows across the broad universe using verified DAILY_ADJUSTED writer markers `alphavantage_daily` and `av_daily_backfill`, rather than only SPY/IWM/QQQ. Require non-NULL adjusted_close for every applicable persisted row. Exclude intraday-derived daily fallback rows, placeholder rows and native index contracts that do not supply adjusted_close; test these exclusions explicitly. The detector reports per-symbol numerator/denominator and the expected session. An empty applicable settled-day universe is unknown/incomplete, not 100% coverage. This check measures field completeness of observed rows; it does not establish that every requested symbol landed.

### Indicator fields, timestamp repair and activation prerequisites

Required source fields for every SPY/IWM/QQQ ticker and both daily and 15min intervals are `av_adx`, `av_mfi`, `av_chaikin_ad_osc`, `av_aroon_up`, `av_aroon_down`, `av_roc`, `av_bbands_upper`, `av_bbands_middle` and `av_bbands_lower`. Derived bandwidth is not a substitute for any source field. Aggregate each field's non-NULL numerator and row denominator independently, require complete fields on the settled session, and report a missing ticker/interval session even if another ticker is complete. Tests null each of the nine columns individually for both intervals and verify that row presence or one canary field cannot pass a partial function response.

Activation depends on the approved specs `docs/superpowers/specs/2026-10-12-feat-data-001-av-indicators.md` and `docs/superpowers/specs/2026-10-12-feat-deploy-001-av-deployment.md`. Before enabling `AV_INDICATOR_COVERAGE_ENABLED`, their implementation must be merged, the deployed writer must normalize naive Eastern intraday timestamps to actual UTC instants, the schedule must be configured, and its first bounded refresh must be verified against AV. For each audited session use newly fetched timestamp-correct observations, or verified bounded replacement of its legacy keys under the IND repair contract; unrepaired legacy timestamps cannot establish complete coverage. Never shift or delete unverified legacy values from OPS.

`AV_INDICATOR_COVERAGE_ENABLED` defaults false and emits a visible planned/incomplete skipped check with the prerequisite explanation. That state allows safe incremental rollout, but cannot satisfy the parent execution milestone for production indicator monitoring or support a claim that monitoring is operational. Code-PR acceptance consists of the prerequisite/activation regressions and complete verification runbook; it does not require deploying unmerged code. After code merge, actual verification is mandatory before overall execution completion. Record merged dependency SHAs, deployed digest, refresh execution, reconciled dates/fields and the enabled watchdog execution before completion. Daily business-date keys remain UTC midnight; intraday query bounds are Eastern midnight through next Eastern midnight converted to UTC, including evening AV bars whose UTC date is the following day.

### One actual exchange calendar

All settled-session and gap-window calculations used by these checks must use the existing fail-closed NYSE calendar primitive `gcp.fetchers.evaluate_ew_strikes.nyse_sessions` (actual UTC market_open/market_close with half-days), also required by the approved options dependency `docs/superpowers/specs/2026-10-12-feat-option-001-av-options.md`. No new shared module or calendar extraction is required; record the reviewed primitive/dependency revision in the plan/runbook. No hard-coded holiday set, weekday approximation or fallback is permitted. Missing dependencies, calendar exceptions or empty/unavailable schedules produce unknown/incomplete results and nonzero strict exits.

Indicator settlement is 04:00 Eastern following a completed exchange session. Choose the latest session whose actual market_close has passed and whose following-day 04:00 Eastern settlement has passed; do not make today's data due merely because the clock passes 04:00. Other existing writer-specific settlement/lag contracts remain explicit and resolve over actual session dates. Bound windows by real session dates and real closes rather than treating Black Friday as closed or imposing a full-day close on its half-day. Regression fixtures include 2026-11-27 (13:00 Eastern close, still a trading session), 2027-01-18 (NYSE holiday), summer/winter DST conversions and calendar-load failure.

### Served earnings-options coverage and lifecycle

`earnings_options_snapshots` feeds the served `earnings_event_outcomes`/`earnings_ticker_lean` path and cannot be dismissed as orphaned solely because its last write is historical. Depend on the approved OPTION spec's merged exact event/prior-session mapping and source-completeness contract. Use one grouped bounded check for the recent event slice required by that consumer: compare expected eligible events and their exact prior NYSE session against verified complete chains, with event identity/provenance. Missing eligible event/session chains report stale/incomplete with the writer and recovery command; SQL/calendar/schema errors report unknown. A no-eligible-events result is a visible legitimate skip with its inspected event window, not a missing-chain alarm. The window, event limit, supported symbols and source-unavailable handling must equal the merged options consumer/repair contract, not an invented recurring daily expectation. Regression tests cover Monday, holiday, complete event, missing chain, no eligible event, schema error and bounded query count.

Until that dependency is merged and reconciled, show the served earnings-options surface as dependency-incomplete. Code-PR acceptance verifies the dependent contract with fixtures and supplies the exact post-merge verification procedure; actual served-consumer reconciliation remains a mandatory parent execution milestone. Historical research flow/GEX stores retain explicit research/historical-only classifications and recovery instructions; they are not promoted to active current feeds. Coordinate genuine gamma no-crossing semantics with OPTION; do not require a fabricated gamma_flip or redefine its financial availability here.

### Active registry index/reference watermarks

OPS owns integrating the fixed allowlisted DATA registry freshness declarations into the existing shared watchdog; DATA owns their schema/validator and per-feed contracts under `docs/superpowers/specs/2026-10-12-feat-data-001-av-market-data.md`. Monitor `INDEX_DATA`, `INDEX_CATALOG`, `ETF_PROFILE`, `DIVIDENDS`, `SPLITS` and `LISTING_STATUS` only after their first source-verified feed and declared lifecycle is active. Planned/disabled/unconfigured entries produce explicit dependency-incomplete/skipped evidence, not healthy freshness; this cannot satisfy the parent overall-execution milestone. No monitor imports an unmerged sibling module. Registry owner, expected symbols, cadence, grace and thresholds come from the merged typed declarations; reject unknown function/table identifiers, malformed timestamp or lifecycle declarations rather than generate SQL from registry strings.

Use one fixed grouped SQL check for the active index/reference feeds, returning at most eight function groups with bounded per-symbol facts inside each group. The query uses only approved fixed destinations: successful, validated `av_response_journal` receipt identities plus exact index session watermarks from `market_data_daily` with `data_source='av_index_data'`. Preserve symbol-scoped facts so a fresh SPY profile cannot mask a missing IWM profile. Grouping by function is a result shape, not permission to ignore requested symbols. There are no per-feed/symbol SQL round trips and no dynamic SQL identifiers/predicates interpolated from registry configuration. The exact DATA receipt interface is `av_response_journal.validation_status` with enum values `validated`, `validated_empty` or `failed`, plus `rows_normalized`. Parse and validate the known enum, a nonnegative integer count, function/symbol identity and fetched_at before evaluating the watermark. The accepted receipt and its normalized rows publish atomically; `validated` requires positive `rows_normalized`, while an accepted `validated_empty` receipt has zero normalized rows. `failed`, unknown/null statuses, missing/inconsistent counts or an archive without this validated atomic-publication contract cannot establish freshness. Raw archive existence or a request made is not success.

INDEX_DATA measures its stored exact latest completed NYSE session, applying the registry's actual-close cutoff and next scheduled refresh grace; a recent request receipt with an old/missing index bar is not fresh. INDEX_CATALOG requires a successful receipt covering the last scheduled completed NYSE session refresh, using the declared 23:15 Eastern run and 30-minute grace; absolute age is reported separately, so a valid Friday receipt does not produce a false Monday-morning or holiday alert. OPS consumes this DATA calendar/grace declaration instead of inventing an exception. Weekly profiles/listing/actions use the successful validated receipt's fetched_at watermark and an eight-day threshold, not the historical corporate-action event date. A `validated_empty` receipt is eligible only for DIVIDENDS/SPLITS or INDEX_DATA with an explicitly proved no-NYSE-session requested window. It must have `rows_normalized=0`; the index no-session receipt never substitutes for a required completed-session bar. A valid empty action receipt counts as a successful fresh observation. Empty INDEX_CATALOG/ETF_PROFILE/LISTING_STATUS, missing receipts, null/unrecognized statuses, inconsistent row counts or null/unparseable watermarks cannot pass. Source/schema/query/registry ambiguity produces unknown and strict exit 2; an absent/stale required active feed produces stale and strict exit 1. Recovery owner and bounded commands are the DATA declarations/runbook, surfaced in alerts through existing freshness routing.

Fixture tests in `tests/audits/test_audit_data_freshness.py` must cover stale weekly age, missing receipt, validated-empty actions, empty-invalid reference feeds, one missing expected symbol hidden by a sibling, index old-session/recent-receipt mismatch, disabled/planned versus active lifecycle, malformed registry/receipt timestamps, each validation_status/rows_normalized combination, failed/archive-only receipts, disallowed empty catalog/listing/profile and declared calendar/grace behavior. Assert one query, <=eight result groups, explicit timeout and fixed SQL. The code PR can prove this integration through fixtures before active deployment; the parent post-merge smoke must then verify actual receipt/table availability, activated lifecycle and alerts before calling the new feeds monitored.

### Durable terminal telemetry

Instrument the two CLI job entry points (`audit-infra-drift` and `freshness-watchdog`) through `gcp.database.record_job_run` on every terminal path, including completed clean/drift, stale, unknown/partial, no configuration, calendar/query exceptions and failed alert delivery. Interactive calls to `audit_all` do not create scheduled-job runs. Persist execution identity, started/finished timestamps and duration, checks/items total/processed/failed, finding count, expected-session/data watermark, terminal status, sanitized error class and `CLOUD_RUN_TASK_ATTEMPT` retry number. Existing job_runs columns hold identity/counts/duration/status; use a bounded structured JSON note for watermark, finding count, retry and error class without requiring unrelated schema changes. Log the same bounded terminal record, including failed telemetry persistence, so a DB outage cannot erase the outcome.

The cleanup helper must not mask an already decided failure. If telemetry persistence returns false or the database is unconfigured/unavailable, emit explicit `telemetry_unavailable` structured evidence to Cloud Logging (and the captured smoke log) and return nonzero incomplete status; do not pretend a DB write succeeded or rely on the unavailable DB to prove the failure. Tests exercise every terminal branch, assert one attempted terminal record with required fields, and assert fallback logging/nonzero exit on failed persistence. Missing Cloud Run identity in local tests uses a generated local run identity, not an invented production execution.
