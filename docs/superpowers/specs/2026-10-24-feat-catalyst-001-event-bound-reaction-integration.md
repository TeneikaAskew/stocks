## Problem and actual evidence

Main `05ab15fcc762e0ce02ddd4ce654604375dbb93df` production `fetch_calendar_timing_map` groups every calendar date by ticker/time, and `populate_for_tickers` looks up ticker alone. A later AMC majority can therefore assign AMC to an earlier BMO event. `normalize_timing(None,None,None)` returns AMC. The retained zero-I/O actual-function witness demonstrates these behaviors on synthetic grouped rows; it does not claim those values were observed in the database. Previously reviewed fixes add explicit local admission entrypoints, but do not repair this production fallback. `earnings_event_outcomes` separately deduplicates history and reaction rows then joins only ticker/report date; the proposed identity check also binds fiscal period.

## Additive `daily_path_v1` contract

Keys: `version`, `event_id` (ticker/fiscal period/reported date), `reaction_basis`, `timing_source`, `source_mode`, `basis_id`, `computed_at`, `observation_ts`, `input_identity`, `status`, `reason`, `gap_sign`, `reaction_session`, `pre_gap_close_session`, `window_end_session`, `mature_at`, `expected_steps`, `observed_steps`, `first_opposite_close_step`, `first_opposite_close_date`, `closing_gap_fill_step`, `closing_gap_fill_date`, `censored` and per-metric availability. Dates/instants serialize ISO-8601 with explicit timezone; no full raw price path is persisted in this field. Inputs/anchor identity is auditable from the existing reaction raw anchor columns and source hashes/receipts; do not persist private credential-bearing manifests.

Freeze definitions from the already completed daily research: reaction session is D for BMO, D+1 for AMC; initial gap direction is reaction open versus the prior regular close. Step 0 is reaction-day open to its completed close; subsequent steps compare successive completed closes. First opposite is the first strictly nonzero sampled closing step opposite initial gap direction. It is **not** a full reversal or evidence of continuous intraday motion. Closing gap fill is independently the first completed close at/beyond the pre-gap close in the direction opposing the gap. No intraday high/low/tick ordering is inferred.

Preserve native terminal D+5 (D is the first canonical trading date at/after reported date): six sampled closes for BMO, five for AMC. Preserve native sustain anchors D close (BMO), D+1 open (AMC), the native reversal sign/magnitude rule and all thresholds. Do not rename/rewrite `is_reversal_5d` as either new metric. Before an observed endpoint is complete it is unavailable; an unresolved pre-endpoint first occurrence is not a completed negative. A first observed occurrence requires a complete prior sampled prefix. At the completed native endpoint, no occurrence with complete data is right-censored at that endpoint, not proof of never reversing. Missing earlier samples make first occurrence unidentifiable and remain unavailable; no fill/interpolation. Zero gap is not-applicable, not up/down. Each aggregate reports eligible/observed/unavailable/not-applicable/censored counts and its own denominator; no success probability or returns claim.

`daily_path_summary_v1` is a separate latest-at-most-12 prior-distinct-mature-event descriptor, with actual event list and separate per-metric denominators. It does not change existing ticker-lean scores or historical native metrics. The existing upcoming JSON carries the newest three event-level records, not an invented three-event classifier.

### Refresh preservation and revision policy

A missing, immature, unrecognized or otherwise rejected candidate is **not** an instruction to erase an existing qualified value. For the same ticker/fiscal/report event, price basis and rule version, preserve each previously qualified legacy field and the exact previous mature `daily_path_v1` payload, including its original `computed_at`, `observation_ts` and input identity, whenever replacement inputs for that field/payload fail admission. Never overwrite it with NULL, an empty object, an unavailable marker, false or zero. New rows with no prior qualified value retain explicit NULL/unavailable state; NULL remains unknown, not a negative outcome. A refresh refusal is recorded by event, metric and reason in the existing job receipt; it must not masquerade as a freshly recomputed observation. A previously stored value lacking qualification evidence is not retroactively certified by retention.

`mature_at` denotes the measurement endpoint's actual completed-session availability, `observation_ts` the admitted decision/data cutoff, and `computed_at` actual computation time; none stands in for original publication/ingestion vintage. A fully admitted replacement must use a complete compatible input prefix and commit the dependent legacy fields and sidecar atomically. A different event date, basis or rule identity cannot inherit an old sidecar: reject the conflicting event update before persistence with an explicit revision-required reason, preserve the prior stored row, and require a separately evidenced correction/revision rather than silently retaining prices under a changed event key. The persistence test must independently exercise unknown timing, immature endpoint, missing basis, missing interior bars, all-null candidate values and conflicting event identity, assert exact retention of prior qualified values/JSON, and prove that a complete compatible candidate can replace them. This is a contract for later implementation, not evidence a database refresh has already passed.
