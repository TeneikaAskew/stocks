## Problem (verified on main be2dd4d1)

1. **No ingestion receipt exists.** Jobs write `job_runs` (`gcp/schema.sql:5133`, via `gcp/database.py:1091 record_job_run`) with counts and a free-text note, but nothing records, per source and scope, when data was observed, when it became available, when it was fetched, what coverage was achieved or why it failed. Freshness checks (`scripts/audit_data_freshness.py`, behind `/api/health/freshness`) read write timestamps, so a fresh write of empty or partial data reads as current.
2. **Benzinga failures read as empty success.** `scripts/fetch_catalyst_calendar.py:121 fetch_calendar` sends the key both as an `Authorization: token` header (line 127) and a `token` query parameter, sends a top-level `date_from` (line 132), returns `[]` on 401 and 403 (lines 147 to 152), `break`s and returns the rows so far on any transport error (lines 171 to 173), logs the exception text (line 172, whose URL carries the token), and stops at 10000 rows without saying so (line 166). `fetch_all_catalysts` (line 474) runs every type with no shared budget. `normalize_generic` (line 367) gives economics rows ticker `""` and drops the provider `id`. The API's `_fetch_live_events` (`platform/api/routers/catalysts.py:140`) calls it on `refresh=true` with caller-chosen dates and tickers.
3. **Credentials leak through error text.** `platform/api/routers/live.py` returns `detail=f"Alpha Vantage request failed: {exc}"` at lines 212 (`get_live_quote`), 480 (`get_live_history`) and 586 (`get_avg_volume`); a `requests` error's text includes the URL and its `apikey`. `lib/ticker_info.py` logs the same exception (GLOBAL_QUOTE path, lines 450 to 495) and `gcp/fetchers/fetch_insider_transactions.py:66` logs it for INSIDER_TRANSACTIONS.
4. **Macro actuals are lost or flattened.** `gcp/fetchers/fetch_economic_events.py` reads FRED and ForexFactory only and persists with `upsert_dataframe(df, 'economic_events', ['event_date', 'event_name'])`, so the 07:00 schedule-only run overwrites a known `actual` with null. The table (`gcp/schema.sql:1455`) holds `actual`, `forecast` and `previous` as VARCHAR. The events route maps `str(r.get("actual") or "")` (catalysts.py:465), so 0 and missing both become `""`. The ticker filter (catalysts.py:285 to 286) drops macro events. Four consumers read `economic_events` with no cutoff: `gcp/premarket_brief.py:897 load_economic_events`, `lib/strategies/catalyst_proximity.py:185 _nearest_economic`, `gcp/research/magnitude_engine/mag_dataset.py:105 _add_phase3_features`, `scripts/check_event_window_concentration.py:43 load_high_impact_events`.
5. **Events defaults follow the wall clock.** `get_catalyst_events` (catalysts.py:163) defaults to `datetime.now()` minus 3 and plus 14 days and accepts `refresh` with no `as_of`, so a historical read cannot be reproduced.
6. **Insider coverage is silent and double-countable.** AV INSIDER_TRANSACTIONS returns nothing for some tickers (AAPL among them in the predecessors' capture), and `fetch_insider_transactions.py --max-tickers` truncates the universe (lines 184 to 187) without a receipt. The `insider_transactions` unique key includes the nullable `shares` and `share_price` (`gcp/schema.sql:992` to 1008), so two rows differing only by a null both persist. Five readers query the table directly: `_db_catalyst_events` (catalysts.py:526), `get_catalyst_snapshot` (catalysts.py:745), `lib/agents/ranker/signals.py:416 _insider_window`, `lib/agents/ranker/candidates.py:137 _candidates_from_insiders`, and `gcp/earnings_reactions_brief.py:437 load_insider_net_flow`.
7. **A quote of any age or kind overlays the daily bar.** `platform/api/routers/dashboard.py:261 _apply_live_overlay` uses the quote price whenever it is above 0 (lines 297 to 299). Neither the live quote nor the watchlist add response (`platform/api/routers/insights.py:518 TickerQuoteResult`, `:535 WatchlistAddResponse`, `:599 POST /api/insights/watchlist/add`) says whether the quote is realtime, delayed or end of day, or when it was observed.
8. **Fixed offsets release dependents on time, not completion.** `gamma-levels-daily` runs at 22:30 ET (`gcp/deploy.sh:4522`) and `strat-engine-daily` at 23:35 (`:4524`) whatever happened to `av-options-daily` at 21:00 (`:4690`) and `fetch-market-data-daily` at 23:00 (`:4645`). A failed or one-sided options run still feeds gamma and STRAT, and `gcp/failure_notifier.py:743 reconcile_closures` closes a job's issue when its latest execution succeeds.

## Approaches considered

1. Patch each fetcher's error handling in place. Rejected: it fixes the symptom per file, and the four macro consumers, five insider readers and two freshness readers would each need their own definition of "current".
2. One receipt and verdict primitive that every changed fetcher writes and every changed reader assesses, with immutable versions for the facts that later consumers replay. Chosen. It is the shared verdict FEAT-CATALYST-001 names as absent, and the version selector is what FEAT-INSIGHT-001 consumes.
3. Keep raw payloads in a storage bucket with an access allowlist. Rejected after #1442's second review: the allowlist could not be proven enforceable without an IAM change. A Cloud SQL table with a trigger enforces create-only and the retention floor in the same database the receipts live in.

## Design

### A. Source receipts and the freshness verdict

New `lib/source_receipts.py` (pure, no I/O):

- `SourceReceipt` (frozen): `receipt_id`, `source` (for example `benzinga.economics`, `sec.form4`, `av.global_quote`), `scope` (ticker, calendar type or `*`), `status` (`complete`, `partial`, `failed`, `unavailable`, `deferred`), `reason` (closed vocabulary, for example `cap_exhausted`, `http_401`, `http_403`, `http_429`, `transport_error`, `refresh_budget_exhausted`, `raw_budget_exhausted`, `deferred_type`), `observed_at`, `available_at`, `fetched_at` (each aware or None; a naive value raises), `coverage` (requested and achieved window, row count), `raw_sha256` (or None), `job_run_id` (or None for an API-path receipt), `error_class` and `error_detail` (from `safe_error` only).
- `FreshnessPolicy` (frozen): `max_age`, `allow_empty`, `session_aware` (uses `lib/eastern_time.py` `previous_session`, `latest_session_on_or_before`, `session_close`).
- `assess_source(receipt, *, now, cutoff, policy) -> SourceHealth`, returning `current`, `stale`, `partial`, `failed`, `unavailable` or `unknown`, with the reason and the receipt id. No receipt gives `unknown`. A write timestamp alone never gives `current`.
- `eligible_at(receipt, cutoff) -> bool`: `available_at` is known and at or before `cutoff`.
- `safe_error(exc) -> (error_class, detail)`: the exception class and the request host and path only; every query string, header and URL userinfo is removed, and any known secret value from the environment (`AV_API_KEY`, `ALPHA_VANTAGE_API_KEY`, `BENZINGA_API_KEY`, `FRED_API_KEY`) is replaced. Every changed failure sink (HTTP detail, log record, receipt) goes through it.

New `gcp/source_receipts.py` (SQL): `record_receipt(receipt) -> int` and `latest_receipt(source, scope, *, cutoff=None)`. New table `source_receipts` in `gcp/schema.sql`: `id BIGSERIAL PRIMARY KEY`, `job_run_id BIGINT NULL REFERENCES job_runs(id)`, the receipt fields above, and an index on `(source, scope, available_at DESC)`. It references `job_runs` and never adds a column to it, so it cannot collide with the telemetry spec's `invocation_kind` and `scheduler_job`.

`scripts/audit_data_freshness.py` reads `assess_source` for the sources this spec gives receipts (economics actuals, Benzinga calendars, SEC fallback, live quote) instead of their write timestamps; other sources keep today's check until a later spec gives them receipts.

### B. Raw payload retention

New table `source_raw_payloads`: `sha256 TEXT PRIMARY KEY` (of the uncompressed bytes), `source TEXT NOT NULL`, `byte_length INTEGER NOT NULL`, `stored_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`, `market_date DATE NOT NULL`, `payload BYTEA NOT NULL` (gzip). A trigger refuses every UPDATE and refuses DELETE of a row whose `stored_at` is less than 90 days old. `store_raw_payload(source, market_date, data: bytes) -> RawStatus` stores at most 2 MiB of raw bytes per object (larger is `oversize`, hash only), inserts with `ON CONFLICT DO NOTHING`, and stops storing bodies once the market date's stored gzip bytes reach 50 MiB (`raw_budget_exhausted`, hash only). Request URLs and query strings are never stored; the receipt keeps host and path. `purge_raw_payloads(limit=5000)` deletes only rows at least 90 days old, oldest first, at most `limit` per call, and runs once per weekday at the end of §J's strat phase. Raw retention applies to Benzinga calendar pages, SEC Form 4 documents and AV INSIDER_TRANSACTIONS responses.

### C. Benzinga contract and shared budget

`fetch_calendar` sends the key as the `token` query parameter only, no `Authorization` header, and dates as `parameters[date_from]` and `parameters[date_to]`. This is the contract the predecessors captured; the Part 1 PR re-verifies it against one recorded live response committed as a fixture before merge, and if the provider disagrees the PR stops and reports (Open questions 4). Per page it records a receipt; 401, 403, 429 and a transport error are `failed` with `safe_error` detail, never `[]` and never a silent partial; a row cap reached is `partial` with `cap_exhausted`. `fetch_all_catalysts` takes one `Budget` shared across types: API path at most 2 provider requests and 10 seconds in total (remaining time is each request's timeout); CLI path at most 3 requests per type attempt, 3000 rows and 120 seconds. A type not reached is recorded `deferred` with `deferred_type`, and the next invocation starts from deferred types first. `normalize_generic` keeps the provider `id` and gives economics rows ticker null, not `""`.

Admission: new table `provider_admission(provider, lane, market_date, admitted, lane_limit, PRIMARY KEY (provider, lane, market_date))`. `admit(provider, lane, market_date)` is one `INSERT ... ON CONFLICT DO UPDATE SET admitted = admitted + 1 WHERE admitted < lane_limit RETURNING admitted`; no row returned means refused. Benzinga lanes: `scheduled` 135 per market date (44 due-macro runs times at most 3 pages, plus 3 for the 07:00 schedule) and `api` 20. Every provider request admits first. An API `refresh=true` beyond the `api` lane makes no provider request and returns cached rows with `source_status` `refresh_budget_exhausted`. Single-flight coalescing stays as an optimization; the counter is the bound.

### D. Macro observations

`gcp/fetchers/fetch_economic_events.py` adds Benzinga economics (through §C) beside FRED and ForexFactory. New immutable table `macro_observation_versions`: `version_id BIGSERIAL`, `event_key` (provider and provider id, or provider, country, event name and scheduled time when no id), `scheduled_release_at TIMESTAMPTZ`, `unit`, `period`, `actual NUMERIC NULL`, `consensus NUMERIC NULL`, `prior NUMERIC NULL`, `actual_text`, `consensus_text`, `prior_text`, `observed_at`, `available_at`, `fetched_at`, `receipt_id`, `raw_sha256`, unique on `(event_key, available_at, payload_sha256)`; a trigger refuses UPDATE and DELETE. A revision is a new version. `economic_events` stays as the legacy projection; its upsert keeps a non-null `actual`, `forecast` or `previous` when the incoming value is null (`COALESCE(EXCLUDED.x, economic_events.x)`). `/api/catalysts/events` returns macro values as numbers or null with `actual_status` (`reported`, `unavailable`, `not_due`), so 0 stays 0; macro events are returned under a ticker filter. New `lib/macro_observations.py` holds the parsing (percent, K, M, B suffixes and unit) with the numeric and text forms kept side by side.

### E. Macro consumers at a cutoff

The four consumers in Problem 4 read through one SQL function `macro_versions_as_of(cutoff)` in `gcp/queries/macro_observations_as_of.sql`, which applies `available_at <= cutoff` and picks the latest eligible version per `event_key` before any LIMIT. `load_economic_events` uses the brief's as-of time; `_nearest_economic` uses the bar timestamp; `_add_phase3_features` uses each row's decision time; `load_high_impact_events` uses its window end. No consumer falls back to `economic_events` when no eligible version exists; it records the gap the way it records a missing event today.

### F. `/api/catalysts/events` as of a cutoff

Optional `as_of` (aware ISO). `as_of` with `refresh=true` returns HTTP 400 before any provider or SQL call. With `as_of` and no dates, the window is the cutoff's market date (`latest_session_on_or_before`) minus 3 to plus 14 calendar days; without `as_of`, today's market date as now. Every response with `as_of` carries M4 `temporal_proof` listing each source read, its receipt id, verdict and the versions selected. Per-source count, newest data and write fields remain FEAT-CATALYST-001's (#1303). OpenAPI is regenerated.

### G. SEC Form 4 fallback for AV-empty tickers

New `gcp/fetchers/sec_form4.py`, run by `fetch-insider-transactions` after its AV pass for tickers whose AV receipt is `complete` with zero rows or `failed`. Parser: lxml with `resolve_entities=False`, `no_network=True`, `load_dtd=False`, `huge_tree=False`; any DOCTYPE is refused; documents over 1 MiB are refused; committed fixtures cover a valid filing, XXE, external DTD and billion-laughs. Requests carry `User-Agent` from `SEC_CONTACT_USER_AGENT` (missing means `unavailable`, no request), at most 2 per second, at most 10 filings per ticker, windows of at most 30 days, all inside the job's existing admission. A per-ticker `sec_complete_through` cursor advances only over a window read completely, so a gap is retried, never skipped. New table `insider_form4_transactions` with a non-null unique key `(accession_number, document_name, transaction_index)`, raw transaction code and acquired or disposed flag kept apart, and `nontrade` set for G, F, M, derivative and amendment rows. Buy is P with A; sell is S with D.

### H. One selected insider source

New view `insider_selected_transactions`: for each ticker and transaction date, AV rows when a valid AV receipt for that ticker covers the date and holds rows, otherwise SEC rows that are not `nontrade`; never both. The five readers in Problem 6 read the view with the same columns they read today plus `source`. `insider_transactions` and its unique key are not changed here (AV ingestion is FEAT-CATALYST-001's).

### I. Quote provenance

`lib/ticker_info.py`'s GLOBAL_QUOTE path and `get_live_quote` return `entitlement_requested` (the `entitlement` parameter sent), `entitlement_effective` (from the response, or `unknown`), `latest_trading_day`, `observed_at` (null when the provider gives only a date), `fetched_at`, and `venue` (null with `venue_reason: venue_unavailable` when absent). `TickerQuoteResult` and the nested quote of `WatchlistAddResponse` carry the same fields. `_apply_live_overlay` applies a quote only when `entitlement_effective` is `realtime` or `delayed`, `observed_at` is known, and `assess_source` with the quote policy (session-aware, 20 minutes) is `current`; otherwise it leaves the daily bar unchanged and reports `overlay_status: refused` with the reason. HTTP errors use `safe_error`.

### J. Completion-gated refresh controller

New `gcp/data_refresh_sequence.py`, run as `python -m gcp.data_refresh_sequence scheduled-sequence --phase options-gamma|strat [--dry-run]`, `due-macro [--dry-run]`, and `acknowledge --phase P --session D --reason TEXT` for an operator.

- **options-gamma** (launched by the 21:00 scheduler): launches `fetch-av-options-backfill` with its existing selected universe, waits for that execution's terminal state, checks its receipts with the controller's own SQL (both sides present for every selected ticker under #1490's rule), then launches `p2-build-gamma-levels` only if `now + p95(gamma duration over the last 20 successful runs)` ends before the next snapshot scanner start (scheduler `options-daily-features` launching `build-options-daily-features` at 22:00, scheduler `options-daily-greeks` launching `build-options-greeks` at 23:15); otherwise it waits for that scanner's terminal state and re-checks.
- **strat** (launched by the 23:35 scheduler): launches `strat-engine` only after the same session's gamma succeeded and the controller's SQL shows complete same-session market daily, intraday and VIX coverage from `fetch-market-data`; then purges raw payloads (§B).
- **Launch safety:** before each `jobs.run`, persist `LaunchIntent(intent_id, phase, step, session, target_job, input_hash, state)` and move `prepared` to `submitting` by compare-and-set. An intent in `submitting` without a known execution is `launch_unknown`, never launched again. `reconcile_launch(intent, *, max_pages=3, max_executions=150, deadline_seconds=10)` binds a unique matching execution by compare-and-set or stays `launch_unknown`. Each phase stops within 60 minutes and records where it stopped.
- **Exit status:** a phase that suppressed, deferred or left `launch_unknown` exits nonzero with a structured ERROR. Each phase also reads the prior 5 sessions' phase receipts and exits nonzero while any is failed and neither repaired by a later successful run of the same phase and session nor acknowledged. Because both phases share one job name, this keeps `reconcile_closures` from closing a failed options-gamma incident when the strat phase later succeeds.
- **due-macro** (every 15 minutes, 08:00 to 18:45 ET weekdays): for each admitted release (scheduled at or before 17:45 ET), attempts at the first run at or after release, release plus 30 and release plus 60 minutes, never a fourth; a release after 17:45 is recorded `outside_dispatch_window`. It exits nonzero with a structured ERROR while any admitted release lacks a valid actual 60 minutes after its scheduled time, including a run with no new due work; a reported 0 resolves it, a schedule row does not.

### M. Consumed temporal contract (stable)

This section is what FEAT-INSIGHT-001's re-cut of #1425 consumes. Its names, shapes and semantics change only by a spec that supersedes this one.

- **M1 clocks.** `observed_at` (when the fact was true at the source), `available_at` (when this system could first have known it: the first successful fetch that returned it, or the provider's publication time when the provider states one and it is later), `fetched_at` (transport time of this read). All three are aware; any may be null with a reason.
- **M2 versions.** Table `source_evidence_versions`: `version_id TEXT PRIMARY KEY`, `dataset`, `scope`, `partition_key NULL`, `payload JSONB`, `payload_sha256`, the three M1 clocks, `data_cutoff`, `receipt_id`, `producer_integrity_hash`, `contract_version`. A trigger refuses UPDATE and DELETE. Python type `EvidenceVersion` mirrors it.
- **M3 selector.** `select_evidence_version(dataset, scope, *, cutoff, partition_key=None) -> EvidenceVersion | EvidenceUnavailable` in `gcp/source_receipts.py` returns the latest version with known `available_at <= cutoff` and `data_cutoff <= cutoff`, eligibility applied in SQL before LIMIT. `EvidenceUnavailable` carries `reason`. Options and gamma datasets return `EvidenceUnavailable(reason="options_as_of_owned_by_feat_option_001")`; their as-of visibility is #1490's `revision_visible`. `select_schedule_as_of(source, *, cutoff)` returns a future schedule known before the cutoff without any actual first available after it.
- **M4 `temporal_proof`.** `{contract_version, requested_cutoff, sources: [{source, scope, receipt_id, verdict, reason, version_ids, observed_at, available_at, fetched_at}], excluded_sections: [...]}`.
- **M5 integrity.** `producer_integrity_hash` is lowercase SHA-256 over the UTF-8 RFC 8785 (JCS) serialization of exactly `{contract_version, version_id, payload, temporal_metadata}`, tag `rfc8785-sha256-v1`. `temporal_metadata` has exactly these thirteen fields, with explicit null or empty collections where absent: `source`, `status`, `reason`, `observed_at`, `available_at`, `fetched_at`, `data_cutoff`, `coverage`, `entitlement`, `session`, `dependencies`, `excluded_sections`, `all_payload_fields_covered`. Raw receipt hashes stay byte hashes. JCS comes from a pinned dependency added on its own `chore/` branch, or a local implementation; either passes the committed RFC 8785 vectors.
- **M6 export.** `scripts/export_evidence_contract.py` writes `tests/fixtures/evidence_contract/consumer_contract.json` (the M2 to M5 shapes, the reason vocabulary and the test node ids that prove them); D11 checks it byte for byte.

## Capacity and cost (Rule 0)

Planning ceilings, each re-measured in the implementation PR that adds the workload; a measured value above a quarter of its timeout is reduced, never hidden by a larger timeout.

| Workload | Volume | Velocity | Wall clock and cost |
|---|---|---|---|
| Receipts | about 300 rows per weekday, under 1 KB each | one INSERT per source and scope per run, batched | under 0.1 MB per day; no new job |
| Raw payloads | at most 50 MiB gzip per market date, 90-day floor | one INSERT per object | at most 4.5 GiB at steady state, about $0.77 per month at $0.17 per GB-month; purge at most 5000 rows per weekday |
| Benzinga | at most 135 scheduled and 20 API requests per market date | 2 per API call, 3 per CLI type attempt | API at most 10 s per call; CLI at most 120 s |
| SEC fallback | at most 10 filings per AV-empty ticker | at most 2 requests per second | runs inside fetch-insider-transactions' existing admission; tickers not reached are deferred with a receipt |

| Controller and due-macro | see the companion spec | | about $8.85 per month incremental compute ceiling |

## Risks

- A receipt that says `complete` for a partial read would make the verdict lie: every status is set from the transport result, never defaulted, and D4 and D8 assert the failed and partial paths.
- The Benzinga parameter contract comes from the predecessors' capture, not a fresh read: the Part 1 PR re-verifies it with a committed recorded response before merge.
- The macro version table and the legacy projection could disagree: consumers read versions only, and the projection is written from the same transaction.
- Raw payload growth: the per-day byte budget and the 90-day purge bound it; the trigger blocks early deletion, so a purge bug fails loudly.
- A long gamma run could overlap the 22:00 scanner: the p95 rule waits instead, and D12 tests a slow options run crossing 22:00.
