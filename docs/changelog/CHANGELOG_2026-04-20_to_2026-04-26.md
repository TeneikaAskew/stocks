# Changelog: 2026-04-20 to 2026-04-26

## Session 2 (2026-04-26)

### Cap Earnings-Ticker Fan-out at Top-25 by Tier + Market Cap
- **Files**: `gcp/fetchers/fetch_market_data.py`, `gcp/premarket_brief.py`, `docs/GCP_IMPLEMENTATION_GUIDE.md`
- **What Changed**: `_earnings_tickers_in_window()` (the daily fetcher's earnings-window resolver) now ranks tickers by `optionable DESC, market_cap DESC NULLS LAST, ticker` and limits to a configurable `top_n` (default 25). `load_earnings_for_brief()` does the parallel work for the Discord embed: pulls `market_cap` from `earnings_calendar`, picks the largest non-null cap across the ticker's source rows (UW omits market_cap; we don't want a NULL from one source to outrank a real value from another), sorts by `(date, tier, -market_cap, ticker)`, then caps at `top_n=25` (overridable via `BRIEF_MAX_EARNINGS` env var). Both call sites accept `top_n=0` for the legacy unbounded behaviour. The fetcher's `--max-earnings-tickers` flag and the brief's env var default to the same number so the morning embed surfaces the same names the daily fetcher actually backfills bars for. GCP_IMPLEMENTATION_GUIDE §10 Pre-Market Brief flow updated to document the earnings query, the tier+market_cap sort, and the `top_n` cap.
- **Why**: AlphaVantage allows 150 req/min on the current tier; each ticker costs ~3 calls (intraday + daily + supporting). The full earnings calendar can return 200+ tickers, so a thin earnings week was eating the minute budget before the loop reached IWM/QQQ/SPY — those silently skipped with empty AV responses, leaving the four core tickers stale for ~2 weeks before anyone noticed. The cap stays well under the budget; ranking by has_options + market_cap means the names that are dropped are illiquid, non-optionable junk, not the AVGO-tier ones traders actually care about.
- **Benefit**: Core tickers stay current. The premarket Discord embed and the daily Cloud Run fetcher now name the same tickers, so traders can trust that any earnings name in the brief actually has fresh bars in Cloud SQL.

## Session 1 (2026-04-25)

### Cloud Run Deployment of Trading Platform with IAP SSO
- **Commits**: `93c8a1b`, `cf691c6`
- **Files**: `platform/Dockerfile`, `platform/cloudbuild.yaml`, `platform/deploy.sh`, `platform/api/main.py`, `.gcloudignore`, `platform/playwright.config.ts`, `platform/package.json`, `platform/.gitignore`, `platform/tests/auth.setup.ts`, `platform/tests/dev.spec.ts`
- **What Changed**: First production deploy of `platform/` (FastAPI + Vite SPA) to Cloud Run as service `trading-platform` in `us-east1`. Multi-stage Dockerfile builds the Vite frontend with Node 20, then runs Uvicorn under Python 3.11 serving both `/api` and the SPA via StaticFiles. `cloudbuild.yaml` was needed because `gcloud builds submit --tag` only finds Dockerfile at the repo root — used `--config` with explicit `-f platform/Dockerfile`. `.gcloudignore` was excluding all Dockerfiles globally; anchored the patterns so `/Dockerfile` (root Jupyter image) is excluded but `platform/Dockerfile` flows through. Also added `node_modules/` and `platform/dist/` exclusions, dropping the build context from ~470MB to ~225MB. Cloud SQL connection wired via the `--add-cloudsql-instances` flag and the existing `gcp/database.py` connector path; `gcp/` is now copied into the runtime image. Auto-managed IAP enabled via `gcloud beta run services update --iap`; `roles/iap.httpsResourceAccessor` granted to `teneika@bictech.org` and to a new `playwright-tester` service account. Added `/dev` endpoint that displays the deployed revision, Playwright tester SA email, and IAP audience for diagnostic use, gated to `teneika@bictech.org` via the IAP-injected `X-Goog-Authenticated-User-Email` header. Local-dev requests (no header) bypass the gate. Playwright config grew two new projects: `iap-setup` (headed, captures Google sign-in cookies via `tests/auth.setup.ts` → `tests/.auth/iap-state.json`) and `cloud` (headless, reuses cookies against the deployed URL). New npm scripts `e2e`, `e2e:cloud:auth`, `e2e:cloud`.
- **Why**: User wanted the unified trading dashboard reachable outside the Codespace, with Google SSO scoped to bictech.org. Programmatic SA auth turned out to be infeasible against auto-managed IAP-on-Cloud-Run because the IAP OAuth Admin API was permanently shut down on 2026-03-19 — there is no way to register a custom OAuth client for SA-issued JWT validation. Browser-based SSO and the Playwright `storageState` pattern are the only working paths until Google ships a replacement; switching to IAP-behind-Load-Balancer would unblock programmatic SA auth (and Option A from the IAP playbook) but adds infra cost and was deferred.
- **Benefit**: Cloud Run service `trading-platform-5sjtb3yl7a-ue.a.run.app` is live, signed-in bictech.org users land on the dashboard, Cloud SQL queries succeed (`/api/health` reports `cloud_sql: true`). The `/dev` page gives a single source of truth for who can authenticate and how. Playwright cloud-mode setup is in place so deployed-instance E2E becomes a one-command run after the user does the interactive auth step from a machine with a display.

### WCAG Button Contrast + TypeScript Build Fixes
- **Commits**: `1d07413`
- **Files**: `platform/src/components/charts/PriceAreaChart.tsx`, `platform/src/components/insights/WatchlistPanel.tsx`, `platform/src/lib/playbookEvaluator.test.ts`, `platform/src/routes/AdminPage.tsx`, `platform/src/routes/CatalystsPage.tsx`, `platform/src/routes/ChartsPage.tsx`, `platform/src/routes/InsightsPage.tsx`, `platform/src/routes/LiveMarketPage.tsx`, `platform/vite.config.ts`
- **What Changed**: Replaced eight `bg-[var(--color-accent-blue)] ... text-white` button class strings with `text-[var(--on-brand)]` so the design token's matching foreground (#000 in dark mode, #fff in light) is honored — fixes white-on-light-blue (~1.7:1) which fails WCAG AA. Same fix for the green/red CALL/PUT and SIGNAL pills, switching to `--bull`/`--bear` backgrounds with appropriate text. Production `tsc -b` was rejecting four pre-existing errors that `vite dev` had been tolerating: unused `chartTheme` import, unused `EvalResult` type, unused `ICON_MAP` constant, and a `Bar.time` `string` vs `number` mismatch in LiveMarketPage's review-mode candlestick mapper. `vite.config.ts` switched to `defineConfig` from `vitest/config` so the `test` field is recognized.

Same `text-white`-on-brand pattern propagated across InsightsPage tabs, AdminPage, WatchlistPanel, ChartsPage CALL/PUT, LiveMarketPage SIGNAL pill. The TypeScript errors blocked the multi-stage Cloud Run build because `npm run build` runs `tsc -b` before `vite build`.
- **Benefit**: Active buttons now read at ~12:1 in dark mode (WCAG AAA). Production build runs clean and Cloud Run deploys succeed.

### Ranker: Split Insider Buying vs Selling
- **Commits**: `422cb74`
- **Files**: `lib/agents/ranker/scoring.py`, `lib/agents/ranker/signals.py`
- **What Changed**: Replaced the single `insider_cluster` signal (always positive) with `insider_buying` (+1.5 weight) and `insider_selling` (-1.5 weight). `weighted_score()` now allows negative weights; `max_possible` accumulates `abs(weight)` so `pct_of_max` stays in `[-1, 1]`. Shared SQL fetch extracted to `_insider_window()`.
- **Why**: Heavy insider disposals were treated identically to no insider activity — the score didn't penalize bearish insider behavior.
- **Benefit**: Tickers with cluster selling now drop in rank instead of going unflagged.
