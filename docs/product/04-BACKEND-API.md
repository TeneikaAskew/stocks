# Backend and API Product Plan

**VERIFIED — CODE:** inventory below is extracted from FastAPI decorators. Authentication dependency and authorization must be checked at handler/router level; `Protected/inherited` is not assumed from the UI. Common target: typed request/response, explicit unavailable errors, ownership enforcement, idempotency for writes/jobs, bounded retry, structured telemetry, and table/model provenance.

## Capability map
| Capability | Entry points | Business logic/data | Trigger | Target gap |
|---|---|---|---|---|
| Platform API | `platform/api/main.py`, `routers/*` | `lib/*`, PostgreSQL/GCS | HTTPS | consistent auth/contracts/telemetry |
| Ingestion/analysis jobs | `gcp/**/*.py` | vendors → SQL/artifacts | Scheduler/manual | idempotency, freshness, provenance |
| Discord interactions | `gcp/discord_interactions/main.py` | interaction validation and responses | Discord HTTPS | delivery/auth/replay evidence |

## Job/service operating contract
For every job: **input** vendor/config/as-of; **output** versioned rows/artifact; **authentication** service identity/secret binding; **authorization** least-privilege IAM/database role; **retry** only classified transient failures; **idempotency** stable business key/upsert; **scheduling** version-controlled; **monitoring** `job_runs`, counts, watermark and alert; **recovery** replay from explicit as-of window. Existing implementations vary and are not claimed compliant.
