## Gates

**S, Specified.** The element's entry under UI-SCREENS.md exists with acceptance criteria a
test can be written from, its states, and its data contract. Evidence: the entry's anchor.

**T, Traced.** The Chain row is complete and every citation resolves: endpoint in the vendored
OpenAPI snapshot, handler file and line, tables in `gcp/schema.sql`, producer job and
schedule in `gcp/deploy.sh`, test files. `none` is allowed only with a reason. Evidence: the
date and commit of the verification.

**V, Validated.** The element was observed working against real data through a production
path: a recorded request and response on staging, a `scripts/db_query_cr.sh` result showing
the rows the page needs, or a replay flag (`REPLAY_DATE`, `BRIEF_AS_OF`, `INSIGHT_AS_OF`) for
pipeline-produced data. Reading the code never counts (CLAUDE.md §3.11). Evidence: a link to
the PR or issue comment holding the command and its output, with the date.

**Te, Tested.** Automated tests cover the element and each of its states at every layer the
chain crosses, they pass, and the suite they belong to runs on pull requests in its repo.
Today: stocks pytest runs in the Backtest Pipeline workflow on pull requests to `main`;
solyra Vitest runs in solyra CI; solyra Playwright does not run in CI (solyra#28 is open).
A Playwright-only element therefore cannot tick Te until that closes. The gate shows the
blocker instead of hiding it. Evidence: test file links and a CI run link.

Rules:

- V requires T. Te requires S. S and T are independent.
- A tick is a claim with an evidence entry and date in the same commit.
- Nothing un-ticks automatically. The registry drift check queues the document when its
  declared code paths move; the flagged area's V and Te are then re-earned, not carried.

The API service itself runs as a separate account, `trading-platform-svc@`, set by `--service-account` in [platform/deploy.sh](../../platform/deploy.sh); jobs and the API service are not the same identity.
- Auth is global ASGI middleware, not a per-router dependency (`auth_middleware` wraps every request; `_path_requires_auth` decides per-path). It only verifies a bearer token when `AUTH_MODE=firebase`; `iap` and `open` call through unconditionally.
- Freshness has two independent paths that must be read separately: the standalone `freshness-watchdog` Cloud Run job (hourly during RTH, once after close) that exits non-zero into the failure lane on a stale table, and the on-demand `/api/health/freshness` endpoint the Dashboard widget polls, which wraps the same `scripts/audit_data_freshness.py` module behind a 5-minute in-process cache.
- Design drift carried from the pre-#957 architecture diagrams, per spec §4.5: the dashboard was labelled "no per-user auth" and the platform service "FastAPI + React" in the Claude Design docs. Both predate the #957 split (the SPA moved to this solyra repo; `platform/` now serves the API only, and every `/api/*` route is subject to the `AUTH_MODE` posture described in SHARED-01) and are stale as design labels, not as a statement about the current code.

### Backend notes
- Auth is global ASGI middleware, not a per-router dependency. It verifies a bearer token only when `AUTH_MODE=firebase`; in `iap` and `open` it calls through (see [09-SECURITY-AUTH.md](09-SECURITY-AUTH.md)).

- Boot order (client-side, no backend job feeds this area): `ConfigGate` fetches `/api/config/firebase` once per page load (module-level `bootPromise`), then in `firebase` mode dynamically imports and awaits the Firebase facade before `AuthGate` reads any auth state. A logged-out visit to `/` never pays this cost (issue #26).
- Freshness budget: none, identity and config are read fresh on every boot; `useUser`'s `/api/me` query has a 30-second `staleTime` so a role granted or revoked mid-session converges on the next mount/focus refetch, not instantly.

- SHELL-04, 07, 09, 12-16 name the same handful of endpoints repeatedly because AppShell is a thin composition of independently-fetching widgets (`AuthStatusIndicator`/`useUser`, `MarketSessionBadge`/`useLiveStatus`, `MostActiveBar`/`useMostActive`) rather than one shell-level fetch; each widget owns its own loading/empty/error branch in source, not a shared shell-level state machine.

### Backend notes
- Pipeline order feeding this page, earliest first (all times America/New_York): `fetch-market-data` 23:00 Mon-Fri (`market_data_daily`, `market_data_intraday`) → `strat-engine` 23:35 Mon-Fri via `strat-engine-daily` (`strat_features_5m`, `strat_features_15m`) → `strat-engine` 02:00 Tue-Sat via `strat-enrich-daily` (`strat_features_levels_5m`, `strat_features_levels_15m`) → `backfill-daily-indicators` 02:30 Mon-Sat (heals NULL derived-indicator columns on `market_data_daily`; a second raw-scheduler entry, `backfill-indicators-weekly`, re-dispatches the same job Sundays at 03:00 ET with a `BACKFILL_MODE=full` override) → `phase6-playbook` 04:30 Mon-Fri (`playbook_cards`) → `fetch-news-sentiment-earnings` 06:00 Mon-Fri (`news_sentiment`) → `fetch-insider-transactions` / `fetch-economic-events` 07:00 Mon-Fri → `fetch-premarket-refresh` 08:20 Mon-Fri (writes only `gap_pct`/`pre_*` on `market_data_daily`, inserting today's row without OHLC when it is absent) → `premarket-brief` 08:30 Mon-Fri (`premarket_analysis`) → `insight-pipeline` 08:45 Mon-Fri (`insight_reports`) → `fetch-av-options-realtime` every 5 min 09:00-15:59 Mon-Fri (`etf_options_snapshots`, REALTIME) → `magnitude-inference` 09:25 Mon-Fri (`magnitude_per_bar_predictions`) → `fetch-earnings-calendar` 19:00 Mon-Fri → `fetch-av-options-backfill` 21:00 Mon-Fri (`etf_options_snapshots`, EOD) → `premarket-playbook-resolver` 21:15 Mon-Fri (`premarket_analysis` outcome columns) → `historical-signals-watchlist` 01:00 Tue-Sat (`historical_signals`, next session). Ordering for `market_data_daily` is enforced by the schedule itself (08:20 refresh runs before the 08:30 brief; the 23:00 nightly fetch is canonical and runs after close); see [05-c §4](infrastructure/05-c-DATA_DEPENDENCIES.md#4-multi-writer-tables-coordination-risks).
- `premarket_analysis` is a 3-writer table (`premarket-brief`, `premarket-playbook-resolver` at 21:15 Mon-Fri, `signal-monitor` at 09:25 Mon-Fri); the brief handler's `WHERE run_kind = 'live'` filter picks among them at read time, and which job produced the row read by DASHBOARD-01 on any given request was not traced further than that filter.
- Freshness the page assumes: the brief bullets read as "today's brief", which per the pipeline order above is not present until 08:30 ET on a trading day; before that the briefing strip shows the `Unavailable` fallback rather than yesterday's data relabeled as today's. `useInsightReport`, `useFetch` (brief/playbook/signals/sectors) all carry a 60s `staleTime`; the playbook query additionally re-polls every 15 minutes in live mode so the server's own `max_age_days` 503 surfaces within that window.
- Review mode (DASHBOARD-15) does not introduce new endpoints of its own: `reviewDate`/`reviewTime` add a `?date=`/`end_date=`/`end_time=` query parameter onto the brief, playbook and signals requests already listed under DASHBOARD-01/02/05, and `useReviewQuote` additionally calls the same `/api/market/data/{ticker}/{date}` (1-minute bars) and `/api/market/reference/{ticker}/{date}` endpoints already listed under DASHBOARD-04/03 to reconstruct a synthetic as-of quote; see [useReviewQuote.ts](https://github.com/TeneikaAskew/solyra/blob/main/src/hooks/useReviewQuote.ts).
- DASHBOARD-21's `assemble_movement_statement` unconditionally assembles four pieces on every call (`lib/movement_statement.py:978-995`): continuation (the GCS-served strat-type model, via `gcp/research/strat_engine/strat_pred_serve.py`), levels/reach-rates (`premarket_analysis`, already listed), expected-move (`magnitude_per_bar_predictions` + `strat_features_{tf}`), and gamma regime (`etf_options_snapshots`, via `lib/agents/summarizers.py:summarize_gamma_levels`'s REALTIME-then-EOD tiered fallback). The continuation piece's `predict_one` (`gcp/research/strat_engine/strat_pred_serve.py:368-375`) also reads Cloud SQL directly, via `load_strat_features_with_levels` (`gcp/research/strat_engine/strat_dataset.py`, called with `include_levels=True`), which LEFT JOINs `strat_features_levels_{tf}` (`strat_features_levels_5m`/`strat_features_levels_15m`, both runtime-created) onto `strat_features_{tf}`. The `strat-engine` Cloud Run job serves four roles in DASHBOARD-21's chain: its scheduled `strat-engine-daily` trigger (23:35 ET Mon-Fri) runs `strat_data_builder` to write `strat_features_5m`/`strat_features_15m`; its separate `strat-enrich-daily` trigger (02:00 ET Tue-Sat, a raw `gcloud scheduler jobs create http` entry in `gcp/deploy.sh`, not a `_schedule` helper call) re-dispatches the same job with a container-override `args` body to run `gcp/research/strat_engine/strat_enrich_levels.py --mode=backfill-all`, writing the two levels tables; a manual dispatch runs a *different* module in the same image, `gcp/research/strat_engine/strat_pred_train.py`, which writes the per-cell GCS files the continuation piece also reads (`model.pkl`, `features.txt`, `classes.txt`, and `metrics_<epoch>.json` or `runs/<run_id>/metrics.json`, per its docstring and its uploads at lines 300-323); and an on-demand dispatch can run `gcp/research/strat_engine/strat_ece_snapshot.py`, which writes the prefix-root `structure_brief_latest.json` that `predict_one` reads for its live-ECE mute (`gcp/research/strat_engine/strat_pred_serve.py:241-249`, `:343`) and has no scheduler trigger (its docstring, lines 14-28, also documents a local run). ### Backend notes
- Pipeline order feeding this page, earliest first (America/New_York, from the trigger crons in [gcp/deploy.sh](../../gcp/deploy.sh)): `fetch-earnings-history` 19:15 Mon-Fri and Sun (`market_data_daily`, through its chained `_run_backfill`) → `fetch-alphavantage-intraday` 21:00 Mon-Sat via `av-intraday-nightly` and 21:00 on the 1st via `av-intraday-monthly` (`market_data_intraday`) → `fetch-market-data` 23:00 Mon-Fri (`market_data_intraday`, `market_data_daily`). The live path waits on none of them: quote and history are AlphaVantage calls made per request, and only avg-volume and the review-mode reads touch Cloud SQL.
- Freshness the page assumes, from its hooks: quote every 15 s (`staleTime` 10 s) and history every 60 s (30 s), both only while `livePolling` · session status every 60 s (30 s) · avg-volume `staleTime` one hour · indicators `staleTime` 10 s, keyed on the bar count, last bar time, price, volume and average volume · the review-mode day bars one hour ([LiveMarketPage.tsx:35-47](https://github.com/TeneikaAskew/solyra/blob/main/src/routes/LiveMarketPage.tsx#L35)). The live router keeps no server-side cache.
- Writers left out of the `market_data_daily` cells, with the lines that exclude them: `backfill-daily-indicators` writes only indicator and Strat columns (`gcp/fetchers/backfill_daily_indicators.py:350-351`, mapped by `gcp/database.py:1044`), and of those the reference handler's `week` block reads only `rsi_14`, which this page does not render · `fetch-premarket-refresh` inserts only `ticker`, `date`, `pre_*` and `gap_pct` (`gcp/fetchers/fetch_premarket_refresh.py:251-252`), a row dated today with no OHLC or `volume` (avg-volume filters `volume IS NOT NULL`, `platform/api/routers/live.py:409`) · `premarket-brief` only deletes rows `WHERE ticker = :t AND close IS NULL` (`gcp/premarket_brief.py:257-258`).

### Gaps
- [#928](https://github.com/TeneikaAskew/stocks/issues/928) (open) is this page's blocking issue in UI-SCREENS.md. It concerns override resolution in `lib/signals.py` (`_latest_overrides`, audit finding C-04). The setup cards do not reach that code: they come from `_build_signals` inside the router ([live.py:680](../../platform/api/routers/live.py#L680)), and the indicators handler never passes a ticker to `lib/signals.py`. No row on this page leads to the issue's code path.
- **An indicators failure renders as a computed result.** Nothing reads `indicatorsQuery.isError` ([LiveMarketPage.tsx:218-219](https://github.com/TeneikaAskew/solyra/blob/main/src/routes/LiveMarketPage.tsx#L218) substitutes `EMPTY_INDICATORS` and `EMPTY_SIGNALS`). A hermetic render on 2026-09-28 with bars and a quote in hand and a failed `POST /api/live/indicators` showed every tile as `--` and both setup cards as `0/0 met 0%`, with no error text anywhere on the page. A `0%` strength is a value the reader cannot tell from a measured one (Rule 4).
- **Every quote failure is reported as a key or rate-limit problem.** `quoteError` is the query's `isError` for any non-OK status ([useLiveQuote.ts:26-27](https://github.com/TeneikaAskew/solyra/blob/main/src/hooks/useLiveQuote.ts#L26)). The same render with a 401 on the quote showed `Live data unavailable, API key not configured or rate limited.` and no sign-in prompt: the page has no `SignInBanner`, and `DataGate` replaces the body only when the user is signed out (LIVE-13).
- **avg-volume falls back to AlphaVantage silently.** On a Cloud SQL failure the swallowing `query_to_dataframe` returns an empty frame and the handler answers from TIME_SERIES_DAILY ([live.py:404-428](../../platform/api/routers/live.py#L404)). A hermetic probe with the connection forced to fail got HTTP 200 with `source: alphavantage` and one TIME_SERIES_DAILY call. The page never reads `source` (CLAUDE.md §3.7.1). The request also carries no date and the query no date bound ([live.py:407-411](../../platform/api/routers/live.py#L407)), so review mode's RVOL divides the review day's volume by the latest 20 sessions.
- **Market data serves the legacy parquet with no marker.** `_load_date_data` falls back to the GCS `raw/data/<ticker>/` parquets when Cloud SQL fails or returns no rows ([main.py:1668-1696](../../platform/api/main.py#L1668)), and the response carries no `source` field. A hermetic probe with the connection forced to fail got HTTP 200 from `gs://adept-mountain-474619-d4-trading-data/raw/data/iwm/minute/iwm_minute_20260220.parquet`, and a missing volume came back as `0` ([main.py:1004](../../platform/api/main.py#L1004)). The page then applies its own `?? 0` to volume in review mode ([LiveMarketPage.tsx:185](https://github.com/TeneikaAskew/solyra/blob/main/src/routes/LiveMarketPage.tsx#L185), no AUDIT marker). The only writer of those parquets is the one-shot `gcp/migrate_to_gcp.py` upload (`upload_raw_parquets`, line 79). 04's table for this route is already recorded in Dashboard's Gaps (area 04).
- **`MARKET_HOLIDAYS_2026` is the only holiday source** ([live.py:109-120](../../platform/api/routers/live.py#L109)). Calling `_is_market_open` on 2026-09-28 returned `(False, 'closed')` for 2026-12-25 10:00 ET and `(True, 'regular')` for 2027-01-01 and 2027-01-18 10:00 ET, so from January 2027 the session bar reports holidays as regular sessions.
- `useReferenceLevels` returns `null` for any non-OK response ([useMarketData.ts:87](https://github.com/TeneikaAskew/solyra/blob/main/src/hooks/useMarketData.ts#L87)), a `return null` in a data-access hook that Rule 4 forbids. In review mode that leaves the synthetic quote's change `null` (the case [reviewQuote.test.ts](https://github.com/TeneikaAskew/solyra/blob/main/src/routes/reviewQuote.test.ts) covers), with nothing saying the prior close failed to load.
- `GET /api/live/history/{ticker}` drops any bar that fails to parse ([live.py:372](../../platform/api/routers/live.py#L372), `except (KeyError, ValueError): continue`) without counting the drop in the response.
- Sources that disagree with the code: 04-BACKEND-API.md gives `via lib/` for `/api/live/status`, `/api/live/quote/{ticker}` and `/api/live/history/{ticker}`, which read the clock or call AlphaVantage themselves. - The page cannot switch ticker itself (LIVE-07): the command palette's ticker entries navigate to `/charts`, and `TickerCombobox` is mounted on Dashboard, Options Flow, Signals, Insights and Journal only.
- No `AUDIT-2026-05-13` marker sits in the handlers this page reads (`platform/api/routers/live.py`, `platform/api/main.py`) or in the `lib/` modules they call, and every route in the rows above declares a `response_model`. The page's own unmarked `?? 0` is recorded above.

### Backend notes
- Pipeline order feeding this page, earliest first (America/New_York): `fetch-fred-rates` 06:30 daily (`daily_rates`) → `fetch-av-options-realtime` every 5 min from 09:00 to 15:55 Mon-Fri (`etf_options_snapshots`, REALTIME, SPY IWM QQQ) → `fetch-earnings-history` 19:15 Mon-Fri and Sun (`market_data_daily`) → `fetch-alphavantage-intraday` 21:00 Mon-Sat and `fetch-av-options-backfill` 21:00 Mon-Fri (`market_data_intraday`, `etf_options_snapshots` EOD) → `fetch-market-data` 23:00 Mon-Fri (`market_data_intraday`, `market_data_daily`) → `historical-signals-watchlist` 01:00 Tue-Sat (`historical_signals`, for the previous session) → `etf-options-retention` 02:00 daily. On the 1st, `fetch-av-options-backfill` also runs at 05:00 and `fetch-alphavantage-intraday` at 21:00. Nothing scheduled produces the backtester's CSVs (Gaps).
- Freshness the page assumes: `useMarketData` and `useReferenceLevels` never go stale (`staleTime: Infinity`) · the dates list five minutes · journal trades 10 s · indicators and signal-series 10 s · similar setups 60 s · the backtester 30 s · gamma levels one hour with `retry: false`. ### Backend notes
- Pipeline order feeding this page, earliest first (America/New_York): `fetch-fred-rates` 06:30 daily (`daily_rates`) → `fetch-av-options-realtime` every 5 min from 09:00 to 15:55 Mon-Fri (REALTIME rows, SPY IWM QQQ) → `fetch-av-options-backfill` 21:00 Mon-Fri (EOD rows for SPY IWM QQQ SPX, from the job's own args, not the trigger's) → `etf-options-retention` 02:00 daily (deletes REALTIME rows older than 30 days) · `fetch-av-options-backfill` again at 05:00 on the 1st. SPX has no realtime producer, so Trinity's SPX panel and any SPX view read EOD rows only.
- Off-list tickers take a different path. `/api/options/dates/{ticker}`, the chain, the live proxy and `/levels` accept SPY, IWM, QQQ and SPX only (`VALID_TICKERS`, `platform/api/routers/options.py:86`, 400 otherwise). The live grid instead fetches REALTIME_OPTIONS on demand for a ticker outside `GRID_SCHEDULED_TICKERS` when Cloud SQL has nothing, writes the rows back (`platform/api/routers/grid.py:594`) and caps each client IP at 10 distinct tickers per 60 s (lines 375-376, 408-436).
- Freshness the page assumes: the live grid refetches every 60 s (`staleTime` 50 s), the historical grid and `/levels` hold one hour, the dates lists five minutes (`STALE_TIME_MS`). Server-side, the live grid is cached 60 s, the historical grid and the chain twelve hours, the dates lists twelve hours behind a newest-date probe, and the live chain proxy five minutes (`platform/api/routers/grid.py:100-101`, `platform/api/routers/options.py:90-116`).
- `daily_rates` is reached two calls deep: `build_summary` and `build_grid_summary` call `get_rate_and_yield` (`lib/gamma.py:1086-1088`, `:1298-1300`), which reads the table strictly (`lib/options_greeks.py:195-205`). An unavailable rate leaves the gamma flip `None` rather than a computed value.
- Writers left out: `compute-spx-greeks-backfill` updates only the `*_computed` columns (`scripts/maintenance/compute_spx_greeks.py:149-155`), which neither the chain query (`platform/api/routers/options.py:562-579`) nor the grid loaders (`platform/api/routers/grid.py:236-254`) select.
- The page itself holds no loading, empty or error state: each view carries its own (OPTIONS-09 to 11). Producer tests: [test_fetch_av_realtime_options.py](../../tests/gcp/test_fetch_av_realtime_options.py), [test_fetch_av_historical_options.py](../../tests/gcp/test_fetch_av_historical_options.py), [test_options_retention_job.py](../../tests/gcp/test_options_retention_job.py), and for the picker's watchlist write [test_watchlist_helper.py](../../tests/gcp/test_watchlist_helper.py). `fetch-fred-rates`: no test found.
