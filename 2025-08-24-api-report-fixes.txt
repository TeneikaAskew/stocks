● Yes, I can confirm the logic for positions less than 7 days old:

  For positions < 7 days old (using 1-minute data):

  1. Data Collection: The system fetches 1-minute data and groups it by trading day. Each day tracks:
    - high: The highest price of all 1-minute bars for that day
    - low: The lowest price of all 1-minute bars for that day
    - bars: Array of all 1-minute bars for detailed analysis
  2. Strike Hit Detection:
    - For Bullish strategies (Long Calls):
        - Checks if the day's high >= strike price
      - If yes, uses the day's high as the hit price
      - Finds which specific 1-minute bar had that high
    - For Bearish strategies (Long Puts):
        - Checks if the day's low <= strike price
      - If yes, uses the day's low as the hit price
      - Finds which specific 1-minute bar had that low
  3. Day Price Recording:
    - Bullish: Always records the day's high (whether it hit strike or not)
    - Bearish: Always records the day's low (whether it hit strike or not)
    - This is stored in day0Hit, day1Hit, etc.
  4. Volume: The volume is tracked at the 1-minute bar level, but the current code doesn't specifically extract the volume at the
  hit price. The bars array contains all the volume data.

  So to answer your question: Yes, for bullish positions it uses the highest value of the day, and if that value exceeds the 
  strike, it marks it as a hit. If it doesn't exceed the strike, it still records the highest value of the day.

  like me to add logic to capture the volume at the exact time of the strike hit?
